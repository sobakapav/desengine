## Requirements

### Requirement: Верстак материализуется как project-aware shell

Система SHALL публиковать `Workbench` как наблюдаемую пользовательскую сущность, привязанную к проекту, workflow и предмету работы.

#### Scenario: Пользователь видит, что у проекта есть верстак
- **WHEN** пользователь открывает страницу проекта
- **THEN** система может показать materialized workbench shell как часть проектной поверхности
- **AND** shell читается как сущность проекта, а не как отдельная скрытая техническая сессия

#### Scenario: Workbench session принадлежит проекту, workflow и subject
- **WHEN** система материализует `WorkbenchSession`
- **THEN** сессия явно связана с `project`
- **AND** сессия содержит ссылку на направляющий `workflow`
- **AND** сессия содержит `subject`, объясняющий, над чем строится shell

### Requirement: Первая волна workbench остаётся generic

Система SHALL материализовать первую волну `Workbench` без ранней типологии верстаков.

#### Scenario: Пользователь открывает generic workbench shell
- **WHEN** система открывает workbench первой волны
- **THEN** shell представлен как generic workbench surface
- **AND** система не требует заранее классифицировать его по отдельному типу верстака
- **AND** это не мешает позже вводить специализированные workbench-линии поверх общего контракта

### Requirement: Верстак первой волны работает только в locked-режиме

Система SHALL честно ограничивать materialized workbench shell режимом прощупывания без допуска к реальной работе.

#### Scenario: Пользователь открывает workbench shell
- **WHEN** пользователь переходит в route materialized workbench shell
- **THEN** система показывает связанный `project`, `workflow` и `subject`
- **AND** явно сообщает, что рабочий режим верстака ещё не открыт
- **AND** пользователь может изучить shell, но не может начать реальную работу внутри него

#### Scenario: Locked shell не притворяется полноценным рабочим местом
- **WHEN** верстак находится в первой materialization-волне
- **THEN** shell не открывает editing, tool execution или выпуск результатов
- **AND** система не создаёт ложного ожидания, будто верстак уже готов заменить главную project surface
