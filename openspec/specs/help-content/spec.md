# Help-контент

## Purpose

Зафиксировать контракт файловой Markdown-справки: пользовательские help-страницы, картинки и Mermaid-диаграммы читаются из корневого каталога `help/` и доступны только через защищённые help-маршруты.

## Requirements

### Requirement: Help-каталог строится из Markdown-файлов

Система SHALL строить страницу `/help` из Markdown-файлов верхнего уровня корневого каталога `help/`.

#### Scenario: Пользователь открывает каталог справки
- **WHEN** пользователь с доступом открывает `/help`
- **THEN** система читает файлы `help/*.md`
- **AND** показывает ссылку на каждую найденную Markdown-страницу
- **AND** каждая ссылка ведёт на `/help/[helpId]`, где `helpId` соответствует имени файла без `.md`

#### Scenario: Система выбирает заголовок ссылки
- **WHEN** Markdown-файл содержит заголовок первого уровня
- **THEN** ссылка в каталоге использует текст первого H1 как заголовок

#### Scenario: Markdown-файл не содержит H1
- **WHEN** Markdown-файл не содержит заголовок первого уровня
- **THEN** ссылка в каталоге использует имя файла без `.md`

#### Scenario: Каталог сортирует страницы
- **WHEN** в `help/` лежит несколько Markdown-файлов
- **THEN** система сортирует ссылки по отображаемому заголовку

### Requirement: Help-страница рендерит Markdown из файлового каталога

Система SHALL отдавать `/help/[helpId]` как Markdown-страницу из `help/<helpId>.md` через существующий `MarkdownContent`.

#### Scenario: Пользователь открывает существующую help-страницу
- **WHEN** пользователь с доступом открывает `/help/[helpId]`
- **AND** файл `help/<helpId>.md` существует
- **THEN** система рендерит содержимое файла через `MarkdownContent`
- **AND** относительные ссылки на help-assets разрешаются от `/help`

#### Scenario: Пользователь открывает отсутствующую help-страницу
- **WHEN** пользователь с доступом открывает `/help/[helpId]`
- **AND** файл `help/<helpId>.md` отсутствует
- **THEN** система отдаёт управляемую страницу `/help/error`

#### Scenario: Пользователь открывает help-страницу с небезопасным ID
- **WHEN** пользователь открывает help URL с небезопасным идентификатором
- **THEN** система не читает путь за пределами `help/`
- **AND** отдаёт управляемую страницу `/help/error`

### Requirement: Help-картинки отдаются из каталога help/images

Система SHALL отдавать файлы из `help/images/` по URL `/help/images/[imgId]`.

#### Scenario: Markdown ссылается на картинку help
- **WHEN** Markdown-страница содержит относительную картинку `images/example.png`
- **THEN** `MarkdownContent` формирует URL `/help/images/example.png`
- **AND** route handler отдаёт файл `help/images/example.png`

#### Scenario: Пользователь запрашивает отсутствующую help-картинку
- **WHEN** браузер запрашивает `/help/images/[imgId]`
- **AND** файл отсутствует или `imgId` небезопасен
- **THEN** система возвращает HTTP-ошибку без чтения файлов за пределами `help/images/`

### Requirement: Help Mermaid-страницы рендерят Mermaid-файлы

Система SHALL хранить Mermaid-исходники в `help/mermaid/` и рендерить их по `/help/mermaid/[mermaidId]` через существующий `MermaidDiagram`.

#### Scenario: Пользователь открывает Mermaid-страницу help
- **WHEN** пользователь с доступом открывает `/help/mermaid/[mermaidId]`
- **AND** файл `help/mermaid/<mermaidId>.mmd` существует
- **THEN** система рендерит Mermaid-исходник через `MermaidDiagram`

#### Scenario: Пользователь открывает отсутствующую Mermaid-страницу help
- **WHEN** пользователь с доступом открывает `/help/mermaid/[mermaidId]`
- **AND** файл Mermaid отсутствует или `mermaidId` небезопасен
- **THEN** система отдаёт управляемую страницу `/help/error`

### Requirement: Help имеет отдельную страницу ошибки

Система SHALL предоставлять `/help/error` как специальную страницу ошибки help-контента.

#### Scenario: Пользователь попадает на страницу ошибки help
- **WHEN** пользователь с доступом открывает `/help/error`
- **THEN** система показывает понятное сообщение об ошибке help-контента
- **AND** предоставляет ссылку обратно на `/help`
