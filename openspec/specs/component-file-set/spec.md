# Контракт набора файлов компонента

Этот документ фиксирует, какой “набор файлов компонента” считается результатом работы системы.

## Purpose

Зафиксировать единый набор файлов React‑компонента, с которым работает система, чтобы итерации LLM и публикация слепков были однозначными и воспроизводимыми.

## Requirements

### Requirement: Набор файлов компонента фиксирован на MVP

Система SHALL оперировать фиксированным набором файлов компонента для каждого компонента проекта.

#### Scenario: Пользователь запускает workflow по компоненту проекта
- **WHEN** пользователь запускает workflow для компонента проекта
- **THEN** система использует фиксированный набор файлов из этого спека

### Requirement: Допустимый рабочий набор файлов зависит от текущего workflow step

Система SHALL ограничивать фактический рабочий набор файлов текущего workflow step только теми `fileId`, которые разрешены `editableFileIds` этого шага.

#### Scenario: В текущем step запрещён `styles`
- **WHEN** текущий workflow step не разрешает `fileId` `styles`
- **THEN** файл `styles.ts` не считается допустимой частью рабочего набора этого шага
- **AND** система не должна создавать или обновлять его как результат работы LLM

### Requirement: Запрещённые рабочие файлы автоматически удаляются

Система SHALL автоматически удалять рабочие файлы из управляемого набора компонента, если они запрещены на текущем workflow step.

#### Scenario: На диске остался запрещённый рабочий файл
- **WHEN** система выполняет workflow action для шага, где этот `fileId` запрещён
- **THEN** система удаляет соответствующий рабочий файл с диска
- **AND** продолжает работу без пользовательской ошибки

### Requirement: Workflow action использует все разрешённые рабочие файлы текущего step

Система SHALL включать в контекст workflow action все рабочие файлы из набора, разрешённые на текущем шаге.

#### Scenario: Пользователь запускает уточнение
- **WHEN** пользователь запускает очередную итерацию
- **THEN** система автоматически включает в контекст все рабочие файлы, разрешённые на текущем шаге

### Requirement: Пользователь не выбирает вводные файлы вручную

Система SHALL не показывать пользователю отдельный выбор input files для уточняющего промпта.

#### Scenario: Пользователь открывает форму уточняющего промпта
- **WHEN** пользователь взаимодействует с формой `iterate`
- **THEN** интерфейс сводится к вводу текста уточнения и запуску

## Набор файлов (MVP)

Для каждого компонента проекта система оперирует фиксированным набором файлов:
- `Component.tsx` — исходный код React‑компонента.
- `Component.stories.ts` — истории Storybook для компонента.
- `styles.ts` — стили (формат уточняется отдельно; на MVP достаточно существования файла и использования в компоненте).
- `props.ts` — контракт пропсов компонента.
- `mock.ts` — примеры данных/моки для демонстрации.

## Базовые требования к набору

- Набор должен быть самодостаточным для:
  - сборки и запуска Storybook;
  - рендера компонента в изоляции.
- Система считает эти файлы “истиной” для текущего состояния компонента проекта.

## Вводные файлы (Input files)

- В workflow action всегда включаются все рабочие файлы из набора, разрешённые на текущем шаге.
- Пользователь не выбирает подмножество файлов вручную.
- Итерация может менять любые разрешённые на шаге рабочие файлы за один запуск LLM.
