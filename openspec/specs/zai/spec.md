# Адаптер Z.AI

## Purpose

Зафиксировать требования к отдельному адаптеру Z.AI в общем LLM-слое лаборатории.

## Requirements

### Requirement: Система поддерживает адаптер Z.AI

Система SHALL поддерживать отдельный адаптер для Z.AI как самостоятельной платформы GLM-моделей.

#### Scenario: Оператор выбирает Z.AI
- **WHEN** конфигурация приложения переключена на Z.AI
- **THEN** система использует адаптер Z.AI для LLM-вызовов

### Requirement: Конфигурация Z.AI задаётся явно

Система SHALL брать параметры подключения к Z.AI из локальной конфигурации приложения.

#### Scenario: Оператор настраивает Z.AI
- **WHEN** оператор задаёт обязательные параметры подключения к Z.AI
- **THEN** система использует их без изменения кода

#### Scenario: Z.AI включён как активный провайдер
- **WHEN** оператор задаёт `LLM_PROVIDER=zai`
- **AND** задаёт `ZAI_API_KEY`, `ZAI_MODEL` и `ZAI_BASE_URL`
- **THEN** лаборатория использует именно эти параметры для LLM-вызовов

### Requirement: Z.AI принимает изображения уровня

Система SHALL передавать изображения уровня в адаптер Z.AI, если они доступны в LLM-запросе.

#### Scenario: Start или iterate выполняется с картинками через Z.AI
- **WHEN** в LLM-запросе есть одна или несколько PNG-картинок уровня
- **THEN** адаптер Z.AI отправляет их провайдеру вместе с текстовой инструкцией

### Requirement: Ошибки Z.AI различаются по типам

Система SHALL различать как минимум следующие классы ошибок для Z.AI:
- неполная конфигурация;
- ошибка авторизации;
- недоступность endpoint;
- таймаут;
- невалидный ответ провайдера.

#### Scenario: Авторизация Z.AI не прошла
- **WHEN** провайдер возвращает ошибку авторизации
- **THEN** пользователь видит понятное сообщение об ошибке доступа к Z.AI
