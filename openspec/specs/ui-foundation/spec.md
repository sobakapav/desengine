# UI foundation

## Purpose

Зафиксировать базовые shell-паттерны интерфейса: канонический `Navigation`, его монохромный визуальный контракт и подход к локальным boundary/fallback для рискованных render-островков.

## Requirements

### Requirement: Глобальная навигационная полоса является каноническим shell-паттерном

Система SHALL использовать `Navigation` как канонический верхний shell-компонент product-shell интерфейса.

#### Scenario: Команда добавляет или меняет product-shell страницу
- **WHEN** страница относится к product-shell интерфейсу
- **THEN** она использует общий `Navigation`, а не локально собранный верхний набор ссылок

### Requirement: Product-shell использует жёсткий монохромный shell-контракт

Система SHALL рендерить product-shell в чёрно-белом интерфейсном контракте: белый фон, почти чёрный текст и границы, прямые линии, пунктирные secondary callout-блоки и отсутствие скруглений.

#### Scenario: Пользователь открывает любую product-shell страницу
- **WHEN** product-shell страница отрисована
- **THEN** её shell-рамка использует только чёрный, белый и оттенки серого
- **AND** surface не используют цветовые акценты как основной способ различения состояний
- **AND** интерфейсные блоки строятся на прямоугольных рамках без скруглений

#### Scenario: Product-shell показывает вторичный поясняющий блок
- **WHEN** страница рендерит secondary explanation, review note или locked-state notice
- **THEN** этот блок может использовать пунктирную рамку
- **AND** остаётся в том же монохромном контракте без цветовых акцентов

### Requirement: Рискованные render-островки shell-интерфейса предпочитают локальные boundary/fallback-страховки

Система SHALL в product-shell интерфейсе предпочитать локальные boundary/fallback-страховки вокруг рискованных render-островков, если их добавление не вносит заметной архитектурной цены.

#### Scenario: Команда работает с динамическим render-островком
- **WHEN** shell-интерфейс рендерит динамический, пользовательский или иной потенциально нестабильный UI-островок
- **THEN** review проверяет, можно ли почти бесплатно изолировать его локальным boundary/fallback
- **AND** при положительном ответе такой boundary/fallback должен быть добавлен

#### Scenario: Команда оценивает простой статический shell-компонент
- **WHEN** компонент не рендерит рискованное динамическое содержимое
- **THEN** система не требует механически оборачивать его boundary только ради единообразия
