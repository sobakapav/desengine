## Тестовая часть change

Затронутые OpenSpec capability/scenarios:
- `navigation`: сценарии входа на системную страницу и видимости нового пользовательского блока.
- `resource-status`: сценарии совместного отображения анонса и ресурсной диагностики на системной странице.

Уровни проверки:
- static/contract: обязателен.
- unit: обязателен для конфигурационного чтения и fallback-логики, если они выделяются в отдельные функции.
- component/browser: обязателен, так как change меняет пользовательскую системную страницу.
- integration: по необходимости, если появится отдельный route/server-boundary для загрузки анонса.
- e2e smoke: по необходимости, если понадобится сквозная проверка top-level входа.
- live/provider: не требуется.

Команды запуска:
- `npm run test:traceability`
- `npm run test:unit`
- browser/e2e-команда должна быть уточнена в ходе реализации после выбора точки проверки системной страницы

Mock/fixture-данные и credentials:
- fixture-данные должны покрывать хотя бы один успешный Markdown-анонс и один fallback-сценарий недоступного внешнего источника;
- live credentials не нужны.
