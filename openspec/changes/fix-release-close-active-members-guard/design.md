## Контекст

В проекте уже есть правило, что release управляет delivery-составом через `release_ref`, а не через иерархическое `parent_change`. Этого оказалось недостаточно: без отдельного guard release можно архивировать до того, как закроются все активные members этого состава.

## Решение

1. Зафиксировать в `admin-tools`, что release считается закрываемым только после закрытия или перепривязки всех active implement/fix changes своего состава.
2. Продублировать правило в `tools/README.md`, потому что release пока закрывается административной процедурой, а не отдельной командой.
3. Усилить traceability-слой: если active change ссылается на архивированный release, проверка должна падать с явным объяснением, что release был закрыт преждевременно.

## Риски и ограничения

- Guard ловит ошибку на traceability-слое уже после неправильного архивирования, потому что отдельной `os:close` для release пока нет.
- Правило не меняет процесс закрытия implement/fix changes и не подменяет их собственные verification-команды.
