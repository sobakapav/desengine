## Why

Проекту нужен постоянный стратегический фокус на производственных процессах: как changes формулируются, проверяются, синхронизируются и доводятся до предсказуемого результата.

## What Changes

- Вводится focus-change `focus-workflow` как верхнеуровневый контекст для process/governance ветки.
- Диспетчеры производственного контура становятся потомками этого фокуса.

## Non-goals

- Не внедряет feature-функциональность.
- Не выполняет кодовые изменения сам по себе.

## Acceptance Criteria

- `focus-workflow` отображается в `npm run os`.
- `dispatcher-openspec` привязан как потомок `focus-workflow`.
