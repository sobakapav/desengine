## Why

Чтобы desengine стал инструментом для реальной работы, нужно понимать себестоимость: сколько денег и времени уходит на проект и на конкретные задачи. Сейчас этого слоя нет: затраты «растворяются» в процессе.

Даже если состав метрик пока неясен, уже точно нужно начать **фоновый учёт** как процесс:

- фиксировать события затрат (tokens/time/использование экспертизы);
- агрегировать по проектам/задачам;
- хранить историю, чтобы видеть динамику и делать выводы.

## What Changes

- Вводим слой **Cost Accounting**:
  - сбор событий затрат (cost events) в фоне;
  - агрегация по `projectId` и/или `taskId`;
  - расчёт первичных метрик: деньги, время, использование экспертизы.
- Определяем минимальный контракт данных:
  - событие токенов (LLM usage);
  - событие времени специалиста (manual time);
  - событие применения накопленной экспертизы (skill/аттрактор usage).
- Определяем MVP-представления:
  - итог по проекту/задаче за период;
  - разбиение по категориям (tokens / manual time / expertise usage).
- Определяем требования приватности/контроля:
  - где хранятся данные (MVP локально);
  - экспорт/удаление;
  - исключение секретов (не логируем содержимое промптов, только метрики).

## Non-goals

- Идеальная модель себестоимости (всё сразу).
- Финансовый биллинг/инвойсинг.
- Командная аналитика (позже).

## Capabilities

### New Capabilities
- `cost-accounting`: учёт и агрегация затрат.

### Modified Capabilities
- `projects` / `dev-mode` (если включены): затраты должны быть project-scoped.
- `task-model` (если вводится): затраты должны быть task-scoped.
- `experience` / `attractors` (если включены): использование навыков/аттракторов должно отражаться как событие затрат/экономии.

## Acceptance Criteria

- Есть MVP-контракт событий затрат и агрегатов (что именно пишем и как считаем).
- Учёт работает в фоне и не требует ручного ввода для токенов/LLM usage.
- Есть механизм ручного учёта времени специалиста (даже если минимальный).
- Есть стратегия тестирования (unit + traceability; по мере реализации — integration/e2e smoke) и команды проверки.
