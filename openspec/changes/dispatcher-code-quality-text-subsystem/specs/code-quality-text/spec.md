## ADDED Requirements

### Requirement: Подсистема code-quality-text выделена как самостоятельный quality-контур
Система SHALL иметь отдельную подсистему `code-quality-text` с собственными командами запуска, конфигом правил, waiver-реестром и документацией для людей.

#### Scenario: Разработчик запускает quality-проверку по рабочим изменениям
- **WHEN** разработчик выполняет `npm run quality:text`
- **THEN** подсистема проверяет только рабочие изменения (working tree + staged)
- **AND** отчёт показывает нарушения по правилам подсистемы

#### Scenario: Администратор запускает полный quality-аудит
- **WHEN** администратор выполняет `npm run quality:text:repo`
- **THEN** подсистема проверяет весь репозиторий
- **AND** отчёт пригоден для планирования cleanup-итераций

### Requirement: Подсистема поддерживает совместимую migration-модель команд
Система SHALL сохранить обратную совместимость для существующих entry points и одновременно предоставить новые канонические команды подсистемы.

#### Scenario: Существующий pipeline вызывает legacy-команду
- **WHEN** CI или локальный скрипт вызывает `npm run test:readability`
- **THEN** команда делегирует выполнение подсистеме `code-quality-text`
- **AND** поведение проверки эквивалентно `npm run quality:text`

#### Scenario: Команда переходит на каноническую команду
- **WHEN** разработчик или администратор использует `npm run quality:text*`
- **THEN** они получают тот же quality-результат без зависимости от legacy-названия
- **AND** документация маркирует `quality:text*` как основной путь

### Requirement: Временные исключения управляются формально и прозрачно
Система SHALL хранить временные исключения правил в отдельном waiver-реестре с обязательными полями владельца, причины и этапа закрытия.

#### Scenario: Для legacy-файла вводится временное исключение
- **WHEN** команда добавляет waiver
- **THEN** запись содержит `rules`, `owner`, `reason`, `targetStage`
- **AND** отсутствие любого обязательного поля приводит к ошибке в проверке

#### Scenario: Новое нарушение не покрыто waiver
- **WHEN** quality-проверка находит нарушение в scope
- **THEN** при отсутствии подходящего waiver команда завершается с ошибкой
- **AND** нарушение становится видимым блокером для merge

### Requirement: Обязательный quality-gate не увеличивает стоимость LLM-разработки
Система SHALL выполнять обязательный quality-gate детерминированно, без LLM и без сетевых вызовов, а optional LLM-режим (если включен) SHALL иметь строгие бюджетные ограничения.

#### Scenario: Разработчик запускает обязательный quality-gate
- **WHEN** запускается `quality:text` в обязательном контуре (`test:full` или CI)
- **THEN** проверка не выполняет LLM-вызовы
- **AND** результат не зависит от внешних LLM credentials

#### Scenario: Optional LLM-режим включается вручную
- **WHEN** разработчик явно включает optional LLM-режим подсистемы
- **THEN** подсистема применяет budget cap по токенам и количеству файлов
- **AND** при превышении бюджета автоматически возвращается к deterministic-проверке

#### Scenario: Large PR не вызывает катастрофический рост стоимости
- **WHEN** change затрагивает большое количество файлов
- **THEN** подсистема по умолчанию анализирует ограниченный changed-scope
- **AND** полный режим требует явного запуска отдельной команды
