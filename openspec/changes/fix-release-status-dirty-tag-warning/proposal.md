## Why

Пользовательская жалоба показывает UX-баг статуса системы: после обновления по инструкции пользователь может находиться ровно на релизном теге, но UI сообщает, что система запущена в «нерелизной версии».

Судя по текущей логике, dirty worktree поверх релизного тега попадает в условие `development`, но формулировка сообщения звучит так, будто локальная версия не релизная вообще.

## What Changes

- Уточняется контракт статуса `system-release` для случая «точный релизный тег + локальные изменения».
- UI/диагностика перестают смешивать:
  - работу из нерелизной ветки;
  - работу из релизного тега с грязным рабочим деревом.
- Добавляются проверки на текст и condition release-status для dirty-tagged состояния.

## Impact

- Пользователь получает правдивое сообщение о своём состоянии Git.
- Снижается число ложных bug-report'ов на тему «я обновился до релиза, а система говорит обратное».
