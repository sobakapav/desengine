## Контекст

- `producer-architecture-transform` закрепил, что один из главных приоритетов линии - сделать путь `проект -> компонент -> workflow -> работа` понятным для пользователя.
- В текущем UI основная точка входа уже находится на странице проекта, но часть текстов ещё описывает внутренний runtime/workflow-контур, а не рабочий путь пользователя.
- Самый дешёвый и полезный шаг этой волны - не вводить новый экран, а сделать понятнее уже существующие project/task surfaces.

## Решение

1. Усилить страницу проекта как главный стартовый экран работы:
   - коротко объяснить, что сначала пользователь выбирает проект, потом создаёт компонент, а потом открывает работу над ним;
   - собрать это в явный маршрут, который читается без знания внутренних терминов.

2. Упростить тексты в карточках компонентов:
   - меньше технических формулировок про session/readout/coordinator;
   - больше акцента на состоянии работы и следующем действии.

3. Уточнить экран задачи:
   - явно показать, что задача является рабочей сессией внутри проекта и компонента;
   - сделать связь `проект -> компонент -> работа` заметной и в task surface.

4. Не вводить новую сущность и не возвращать отдельную architecture-transform панель.
   Пользовательский эффект должен проявиться через сам путь работы.
