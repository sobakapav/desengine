## Why

Документ содержит сразу несколько жалоб на preview/runtime:
- “невидимый рендер”, где DOM есть, но Tailwind-классы не применяются;
- периодические render-ошибки, которые сами проходят через несколько часов;
- случаи, где библиотечный компонент или стилизованный результат ломает preview, хотя HTML-заглушка проходит.

Текущее состояние кода подтверждает риск:
- базовый preview CSS в [styles.css](/Users/op/dev/sobakapav/desengine/lib/lab/sandpack-templates/default/styles.css) опирается на `@import "tailwindcss"`;
- unit-покрытие в основном проверяет payload builder, а не фактическое применение CSS в браузере;
- runtime построен на внешнем Sandpack bundler и локальных shim/fallback-ветках, что делает “иногда рендер есть, иногда нет” правдоподобным системным симптомом, а не случайной пользовательской ошибкой.

Для пользователя это выглядит как сломанная лаборатория: код и картинка есть, а превью либо без стилей, либо падает непредсказуемо.

## What Changes

- Доказать и стабилизировать фактическое применение preview CSS/Tailwind в браузерном runtime.
- Отделить ошибки sandbox bundler/runtime от случаев, когда компонент реально несовместим.
- Добавить live browser coverage на стиль-применение, а не только unit-проверку payload.

## Non-goals

- Не переписывать весь preview runtime с нуля.
- Не менять глобальный install-critical стек.
- Не смешивать этот defect с prompt/check quality.

## Impact

- Preview перестанет молча показывать “unstyled DOM” как будто всё в порядке.
- Появится проверяемый контракт того, что Tailwind и preview CSS действительно работают на живом runtime, а не только присутствуют в payload.
