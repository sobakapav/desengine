## Why

Project-facing слой уже позволяет создавать проекты и компоненты, но в пользовательском виде он перегружен внутренними сущностями и недоговорённостями:
- у проекта нельзя настроить идентификатор;
- не видно, где проект реально хранится;
- на странице проекта светятся migration, effective kit и другие внутренние runtime-слова;
- создание компонента формулируется так, будто workflow уже начался, хотя это не так;
- отдельный architecture-transform блок не относится к пользовательской задаче.

## What Changes

- Сделать `title` и `id` проекта редактируемыми как нормальные пользовательские поля.
- Показать пользователю, что проект пока хранится локально в браузере.
- Упростить project page и project registry: убрать migration/effective kit/runtime-dependency wording и architecture-transform блок из пользовательского слоя.
- Переформулировать component create-flow так, чтобы было явно: создание компонента не запускает workflow автоматически; workflow стартует только по кнопке работы с компонентом.

## Capabilities

- `projects`
- `workflow`
- `storage-adapter`

## Impact

- Страница проекта станет ближе к реальному пользовательскому инструменту, а не к диагностическому экрану внутренней архитектурной волны.
- Пользователь сможет осознанно управлять идентификатором проекта и лучше понимать, что происходит с компонентом и workflow.
