## Контекст

В репозитории уже есть несколько источников контекста для уровня:

- общий `overview.md` уровня;
- task-specific `tip.md` или `tip.njk`;
- UI-слой, который должен показывать этот контекст на странице уровня и внутри задачи.

Если пользователь не видит описание третьего уровня, проблема может находиться в одном из трёх мест: чтение контента, выбор приоритета между источниками или финальный рендер/видимость в интерфейсе.

## Цели

- Понять, какой именно слой теряет описание.
- Вернуть пользователю видимый и читаемый контекст третьего уровня.
- Закрыть regression browser-level проверкой, а не только чтением файлов на диске.

## Non-goals

- Не переписывать все onboarding hints.
- Не смешивать этот fix с проблемой нехватки уточнений или общим redesign workbench.

## Направление реализации

1. Сопоставить ожидаемый контент уровня 3 на диске с тем, что реально получает UI.
2. Проверить приоритет `overview` / `tip` / runtime fetch path после обновления до `0.1.11`.
3. Восстановить user-facing рендер и зафиксировать browser regression guard.

## Риски

- Если смотреть только на файловую структуру, можно пропустить проблему чисто на UI/layout boundary.
- Если лечить только UI, но runtime отдаёт пустой контент, regression вернётся в другом месте.
