## Тестовая часть change

Затронутые OpenSpec capability/scenarios:
- `code-readability`:
  - `Добавляется новая экспортируемая функция`
  - `Добавляется новый экспортируемый тип или константа`
  - `В бизнес-логику добавляется литерал`
  - `Значение имеет физическую или техническую единицу`
  - `Изменяемый production-файл превышает размер`
  - `Изменяемый test/storybook-файл превышает размер`
  - `Функция превышает soft-limit`
  - `Функция возвращает ошибку в доменной логике`
  - `На вход модуля приходит nullable-значение`
  - `В экспортируемую функцию предлагается добавить флаг`
  - `Реализуется бизнес-правило, требующее внешнего доступа`
  - `В модуле запускается асинхронная операция`
  - `Добавляется нетривиальный экспортируемый API`
  - `В код добавляется TODO или FIXME`
  - `Переименование или удаление публичной сущности`
  - `Разработчик запускает обязательные проверки change`
- `testing-layer`:
  - `Добавляется capability с quality-правилами читаемости`

Уровни проверки:
- static/contract: обязательный
- unit: обязательный
- component/browser: по необходимости для модулей UI-слоя
- integration: по необходимости для cross-module правил
- e2e smoke: не обязателен по умолчанию
- live/provider: не требуется

Команды запуска:
- `npm run test:unit`
- `npm run test:traceability`
- `npm run test:full` (если change затронул широкий контур)

Mock/fixture-данные и credentials:
- Используются локальные mock/fixture-примеры кода (позитивные и негативные кейсы читаемости).
- Live credentials не требуются.

Если покрытие откладывается:
- Добавить запись в `test/traceability/coverage-plan.json` с причиной, владельцем и `targetStage`.
