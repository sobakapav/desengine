## Why

Кодовая база растет, и стоимость чтения кода начинает напрямую влиять на скорость внедрения и качество изменений. Нужен единый, проверяемый стандарт читаемости, чтобы разработчик быстрее понимал намерение кода без ручной расшифровки.

## What Changes

- Вводится capability `code-readability` с обязательными практиками читаемости для TypeScript-кода и OpenSpec-сопровождения.
- Фиксируется минимальный обязательный набор практик:
  - явные комментарии для экспортируемых функций, типов, констант и нетривиальных файлов;
  - осмысленные имена и запрет неочевидных сокращений;
  - отказ от «магических» литералов в пользу именованных констант;
  - ограничение неявной сложности (глубокая вложенность, смешение нескольких ответственностей в одном блоке);
  - явные soft-limit по длине файлов/функций с обязательным разбиением или документированным исключением;
  - единый контракт ошибок и nullability на границах модулей;
  - запрет boolean-trap аргументов и требование к именованным параметрам;
  - изоляция сайд-эффектов от бизнес-логики;
  - безопасный async-стиль без floating promises;
  - единицы измерения в именах значений (`Ms`, `Bytes`, `Count`);
  - policy для `TODO/FIXME` (владелец + срок закрытия);
  - обязательные usage-примеры для нетривиальных API;
  - deprecation-путь для совместимости при переименовании/удалении.
- Определяется способ проверки соблюдения практик через общий тестовый слой (static/contract + traceability), с явными командами запуска.
- Определяется policy по поэтапному внедрению практик в существующем коде и фиксации временных исключений.

## Capabilities

### New Capabilities

- `code-readability`: контракт на человеко-ориентированные практики читаемости кода и проверку их соблюдения.

### Modified Capabilities

- `testing-layer`: добавляется сценарий проверки, что capability `code-readability` подключен к единому тестовому слою и имеет traceability.

## Impact

- OpenSpec:
  - новый spec `code-readability`;
  - дельта в `testing-layer` для связки с единым тестовым слоем.
- Кодовая база:
  - стандарты комментариев, контрактов и структуры для TypeScript-модулей;
  - статические проверки/скрипты качества читаемости;
  - документация для code review и onboarding.
- Тестирование:
  - обязательные команды `npm run test:unit`, `npm run test:traceability`, при необходимости `npm run test:full`;
  - при отложенном покрытии — обязательная запись в `test/traceability/coverage-plan.json`.
