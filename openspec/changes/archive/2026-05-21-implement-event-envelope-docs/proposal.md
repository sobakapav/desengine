## Why

Если MVP event-линии начинает давать наблюдаемое runtime-поведение, команда должна видеть его не только в коде и тестах, но и в документации.

Без этого foundation changes будут развиваться быстрее, чем инженерное понимание того, как использовать `EventEnvelope`, screen propagation и связанные ограничения первого захода.

## What Changes

- Вводится документационный MVP-change под `dispatcher-doc`.
- Change обновляет документацию для event-линии:
  - где живёт общий `EventEnvelope`;
  - какой runtime-boundary существует для записи события;
  - какой screen flow поддерживает наблюдаемую propagation-механику;
  - что в MVP ещё не поддерживается.
- Документация должна быть полезна и продуктово, и инженерно: описывать наблюдаемую пользу и ограничения.

## Non-goals

- Не заменяет собой code comments и тесты.
- Не добавляет help-страницы внутри продукта.
- Не описывает будущую полную event-систему так, будто она уже реализована.

## Capabilities

### Modified Capabilities

- `testing-layer`: документация синхронизируется с фактическими командами проверки foundation и propagation-сценариев.
- `event-envelope`: у MVP появляется человечески читаемый контракт использования.
- `docs`: event-линия получает отдельное документационное сопровождение.

## Acceptance Criteria

- Есть обновлённая документация по общему `EventEnvelope`, runtime-boundary и MVP propagation flow.
- Документация явно разделяет:
  - что уже работает в MVP;
  - что остаётся foundation-слоем;
  - что отложено на следующие changes.
- Команды проверки и traceability-ожидания в документации не противоречат OpenSpec и тестовому контуру.
