- [x] 1.1 Найти место, где формируется статус синхронности кода с последним релизом.
- [x] 1.2 Найти место, где этот статус отображается на странице состояния ресурсов системы.
- [x] 1.3 Зафиксировать текущий ложный сценарий: система работает на последнем релизе, но показывает ошибочный статус.

## 2. Исправление успешной диагностики

- [x] 2.1 Обеспечить корректное распознавание состояния «код соответствует последнему релизу».

## 3. Проверка отображения

- [x] 3.1 Проверить, что страница состояния ресурсов системы показывает успешный статус синхронности, когда код соответствует последнему релизу.
- [x] 3.2 Проверить, что пользователь не видит ложного сообщения об ошибке в успешном сценарии.
- [x] 3.3 Проверить, что при отсутствии онлайн-доступа к релизу система не показывает тревожный статус.
- [x] 3.4 Уровень проверки: unit + ручная проверка в браузере (component/browser без e2e-автоматизации для этого change).
- [x] 3.5 Unit: обновить/добавить кейс в `test/unit/resource-status.test.ts` и запустить `npm run test:unit`.
- [x] 3.6 Traceability: убедиться, что capability `resource-status` остаётся покрытой, и запустить `npm run test:traceability`.

## 4. Границы change

- [x] 4.1 Не добавлять отдельную обработку сценариев «код не синхронен релизу».
- [x] 4.2 Не расширять change до механизмов восстановления, обновления или принудительной синхронизации.

## 5. Приёмка

- [x] 5.1 Пользователь видит правильный статус синхронности кода с релизом на странице состояния ресурсов системы.

- [x] 5.3 Поведение не зависит от режима запуска системы.
