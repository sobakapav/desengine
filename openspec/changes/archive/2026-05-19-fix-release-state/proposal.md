# Change: fix-release-state

## Зачем

Сейчас система не распознаёт корректное состояние «работаю на последнем релизе» и из-за этого показывает ошибочный статус самой себя на странице состояния ресурсов системы. Пользователь видит ложный сигнал о проблеме и вынужден тратить внимание на несуществующую рассинхронизацию.

## Что меняется

Система должна корректно диагностировать успешное соответствие текущего кода последнему релизу и отображать это состояние как нормальное.

Изменение касается только успешного сценария: когда код соответствует последнему релизу, пользователь должен видеть корректный положительный статус синхронности.

## Что не входит

В change не входит обработка проблемных ситуаций, когда код не синхронен релизу. Не требуется проектировать отдельные сценарии восстановления, предупреждений или исправления рассинхронизации.

## Бизнес-правила

- Диагностика синхронности кода с релизом не должна зависеть от способа запуска системы.
- Сценарии запуска через `npm run start` и `npm run dev` должны приводить к одинаковой бизнес-интерпретации статуса релиза.
- Если у системы нет онлайн-доступа к информации о релизе, это не должно создавать ошибочный статус для пользователя.
- При отсутствии онлайн-доступа к релизу система считает состояние допустимым и не тревожит пользователя ложной ошибкой.

## Пользовательский эффект

Пользователь перестаёт видеть ложное сообщение о проблеме синхронности кода с релизом на странице состояния ресурсов системы.

## Затронутая область

- Страница состояния ресурсов системы.
- Диагностика соответствия текущего кода последнему релизу.
- Отображение успешного статуса синхронности.

## Риски и влияние

Изменение техническое, но пользовательское по эффекту: оно снижает ложную тревожность интерфейса. Основной риск — случайно скрыть реальную проблему рассинхронизации. Поэтому область change ограничена только корректным отображением успешного статуса и поведения при недоступности онлайн-проверки.
