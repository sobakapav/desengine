## Why

Пользователь полагается на `/system`, чтобы понять, готов ли активный LLM-провайдер. Сейчас этот диагноз может быть ложным:

- `llm-network` строится через общий `${endpoint}/models`;
- special-case корректно есть только для `gemini`;
- для остальных non-gemini probe использует `authorization: Bearer ...`, причём в части веток фактически берётся `OPENAI_API_KEY`, даже если активный provider — `claude` или `zai`.

В результате пользователь может увидеть предупреждение о якобы сломанной связи с LLM, хотя проблема только в самой диагностике.

## What Changes

- Сделать `llm-network` provider-aware.
- Привязать probe URL и auth header к активному provider contract.
- Добавить тестовое покрытие для `claude` и `zai`, чтобы `/system` не деградировал обратно в OpenAI-centric диагностику.

## Non-goals

- Не менять продуктовый смысл `/system`.
- Не переписывать тексты всех resource cards.
- Не менять выполнение реальных task LLM-вызовов, если проблема только в диагностике.

## Impact

- Пользователь будет видеть на `/system` достоверную картину готовности активного провайдера.
- Система перестанет путать сетевую недоступность провайдера с ошибкой собственного diagnostic probe.
