## Context

В проекте есть отдельные provider-docs в `docs/*.md`, и они уже выступают внешним контрактом для администратора локальной установки. Для DeepSeek этот контракт сейчас устарел: документация говорит о text-only fallback, тогда как runtime уже перешёл к fail-fast boundary.

Это не просто редакционная мелочь. В desengine выбор активного провайдера влияет на то, сможет ли оператор вообще использовать image-dependent lab-flow. Если документация описывает “работает, но без картинок”, а реальная система говорит “запрос с картинками запрещён”, то ошибка выглядит как неожиданный runtime breakage, хотя на самом деле broken именно docs contract.

## Decisions

1. Профильная документация DeepSeek должна описывать не внутренний transport detail, а наблюдаемое поведение системы.

   Для текущего состояния это означает:
   - text-only запросы возможны;
   - image-bearing lab-flow без vision support не выполняется;
   - оператору нужно либо переключить провайдера, либо не запускать сценарии, требующие картинки.

2. Documentation fix должен быть связан с existing source-contract tests.

   Если `docs/deepseek.md` снова начнёт обещать text-only fallback для image-bearing flow, это должно ловиться автоматизированной проверкой, а не только ручным чтением.

3. Этот change не переоткрывает runtime-дискуссию.

   Решение `fail-fast вместо silent fallback` уже принадлежит `fix-deepseek-vision-contract`. Здесь меняется только документационный слой и его anti-regression guard.

## Risks / Trade-offs

- [Риск] Документация станет слишком технической и перестанет помогать администратору.
  - Mitigation: формулировать ограничение как наблюдаемое поведение и конкретный выбор оператора.

- [Риск] Исправление останется только в `docs/deepseek.md`, а source-contract не защитит от обратного drift.
  - Mitigation: привязать change к `test/unit/p2-source-contracts.test.ts` или эквивалентному статическому guardrail.

## Open Questions
