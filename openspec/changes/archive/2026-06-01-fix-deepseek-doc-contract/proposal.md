## Why

Активный runtime contract для DeepSeek уже изменился: image-bearing `start` / `iterate` / `check` больше не деградируют тихо в text-only, а завершаются явной ошибкой до сетевого вызова. Но пользовательская документация всё ещё описывает старое поведение:

- [docs/deepseek.md](/Users/op/dev/sobakapav/desengine/docs/deepseek.md) обещает, что картинки “не передаются в DeepSeek API”, а текстовый контекст продолжает работать;
- это вводит администратора и инженера сопровождения в заблуждение при выборе активного провайдера;
- фактическое поведение системы становится неожиданным: оператор читает одно, а при первом image-bearing сценарии получает fail-fast ошибку другого типа.

Это уже отдельный user-facing дефект документационного контракта, даже если runtime исправлен правильно.

## What Changes

- Согласовать документацию DeepSeek с текущим fail-fast contract для image-bearing запросов.
- Явно объяснить, что:
  - text-only happy path для DeepSeek допустим только для запросов без изображений;
  - задачи лаборатории, завязанные на картинки уровня, не будут silently работать через DeepSeek без vision-support;
  - при отсутствии vision-поддержки система завершает такой запрос понятной ранней ошибкой.
- Добавить source-contract guard, чтобы documentation drift не вернулся незаметно.

## Non-goals

- Не менять сам runtime DeepSeek-адаптера.
- Не добавлять vision support в DeepSeek.
- Не пересматривать контракты других провайдеров, если для них нет текущего drift.

## Impact

- Администратор локальной установки будет видеть правдивое описание ограничений DeepSeek.
- Поведение системы перестанет расходиться с профильной provider-документацией.
- `fix-deepseek-vision-contract` получит согласованное документационное сопровождение, а не останется скрытым знанием из handoff и unit-тестов.
