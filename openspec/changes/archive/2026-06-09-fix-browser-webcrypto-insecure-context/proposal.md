## Why

Подтверждён browser-side симптом: при открытии приложения в небезопасном `http`-контексте появляется `unhandledRejection` с ошибкой `TypeError: undefined is not an object (evaluating 'crypto.subtle.digest')`. После этого пользователь видит каскад вторичных ошибок, включая `Canceled: Canceled` из Monaco.

Для пользователя это выглядит как случайный развал страницы: вместо понятной диагностики или graceful fallback браузер получает runtime crash.

## What Changes

- Устранить browser-side путь, который требует `crypto.subtle` там, где secure context не гарантирован.
- Зафиксировать, что криптографический access/allowlist-контур не должен зависеть от наличия Web Crypto в клиентском рантайме.
- Добавить регрессионную проверку на boundary между browser/client путём и server-side crypto.
- Обновить пользовательскую/техническую диагностику, если insecure `http`-контекст всё же остаётся ограничением.

## Non-goals

- Не переводить весь локальный доступ по IP на обязательный `https`.
- Не переписывать Monaco или браузерный runtime целиком.
- Не менять allowlist-политику продукта сверх локального устранения crash-path.

## Impact

- Открытие приложения в браузере больше не должно падать только из-за того, что `crypto.subtle` недоступен в текущем origin.
- Если secure context всё ещё нужен для отдельной возможности, система должна объяснять это явно, а не рушить страницу.
