## Why

В текущем preview-flow подтверждён системный дефект: Sandpack может успешно отрисовать React DOM внутри iframe, но не применить preview CSS/Tailwind к probe-элементу и пользовательскому компоненту. В этом состоянии host уже не показывает пустой экран, но и не даёт корректный визуальный результат: пользователь видит либо предупреждение про style contract, либо неподтверждённый рендер без нужных стилей.

Это ломает основной контракт лаборатории: preview должен показывать не просто наличие DOM, а фактический визуальный результат, пригодный для сравнения с референсом.

## What Changes

- Выявить и исправить реальную причину, по которой Sandpack iframe получает DOM без применённого preview CSS/Tailwind.
- Зафиксировать style contract так, чтобы он доказывал применение CSS в живом browser runtime, а не только наличие файлов в payload.
- Добавить проверку, которая различает styled preview, unstyled DOM и runtime outage.

## Non-goals

- Не переписывать весь preview engine и не заменять Sandpack на другой runtime.
- Не менять prompt/check logic, не трогать unrelated workbench UX и не пересматривать архитектуру dispatcher-level решений.
- Не ограничиваться косметическим скрытием предупреждения `unstyled-dom` без реального восстановления style pipeline.

## Impact

- Пользователь будет получать подтверждённый styled preview вместо DOM без стилей.
- Диагностика preview останется честной: если CSS не применился, система не будет выдавать это за нормальный рендер.
- Browser-level проверка начнёт ловить именно сбой style pipeline, а не только падение bundler/runtime.
