## Why

Страница проекта уже умеет создавать компонент и запускать для него workflow, но после первого входа карточка компонента остаётся слишком слепой: по ней не видно, что сессия уже живёт, где пользователь остановился и стоит ли продолжать работу отсюда.

Из-за этого проект пока не читается как основная рабочая точка для серии компонентных workflow. Пользователь видит список компонентов, но не получает простого ответа на практические вопросы: какой компонент уже запущен, какой workflow-run активен и куда нажать, чтобы вернуться в нужную сессию.

## What Changes

- Сделать карточку `ProjectComponent` на странице проекта полноценной точкой продолжения workflow-сессии.
- Показать на карточке состояние workflow-run, последнюю активность и текущий прогресс по пунктам workflow, если runtime уже проявлен.
- Переключить главное действие карточки с первого запуска на понятный `Продолжить работу`, когда у компонента уже есть назначенный backing task и живая/завершённая сессия.

## Capabilities

- `projects`
- `workflow`

## Impact

- Пользователь сможет работать с несколькими компонентами внутри одного проекта, не проваливаясь каждый раз в task list ради поиска нужной сессии.
- Project page станет более реалистичным production-facing входом в workflow-работу.
