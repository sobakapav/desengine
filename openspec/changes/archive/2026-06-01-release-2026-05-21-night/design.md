## Контекст

`release-2026-05-21-night` не меняет код и не вводит новый продуктовый контракт. Его задача уже определена в `proposal.md`: выступать релизной меткой для ночной волны fixes и docs-fix, поднятых из triage пользовательских жалоб.

Проблема текущего состояния в том, что change оформлен неполно для схемы `spec-driven`: отсутствуют `design.md`, `tasks.md` и delta specs. Из-за этого release нельзя штатно довести до архивирования, хотя по смыслу он уже выполняет роль поставочной группировки.

## Решение

Нужно оформить release как документирующий change без расширения поведенческой области:

1. Явно зафиксировать, что release не становится `parent_change` для downstream fixes и не подменяет dispatcher-иерархию.
2. Закрепить состав ночной волны как набор changes, объединённых через `release_ref`.
3. Добавить delta spec только на уровне `admin-tools`, чтобы подтвердить существующий контракт релизной группировки и traceability, а не придумывать новое runtime-поведение.
4. Описать тестовый след как static/contract-проверку оформления и ссылочной целостности.

## Границы

В этот change входит:

- описание релизного состава;
- фиксация роли `release_ref` для данной волны;
- тестовая трассировка на уровне OpenSpec/admin-tools.

В этот change не входит:

- изменение кода продукта;
- изменение стратегической иерархии downstream fixes;
- введение новых CLI-команд, новых ролей change или новых полей metadata.

## Риски и их контроль

- Риск: release будет выглядеть как новый продуктовый контракт.
  Контроль: delta spec описывает только уже принятый механизм группировки через `release_ref`.
- Риск: релизная метка начнёт восприниматься как родительский управляющий контур.
  Контроль: в design и spec явно указано, что `parent_change` для release остаётся пустым, а downstream changes продолжают подчиняться своим dispatcher.

## Проверка

- Уровень: static/contract.
- Команда для внешней проверки: `npm run test:traceability`.
- Что должно подтвердиться: release change оформлен полностью, а downstream fixes/docs-fix сохраняют корректную ссылку на релиз через `release_ref`.
