## Why

Первый проход установки сейчас перегружен лишними развилками и дублирующими настройками. Для неразработчика это выглядит так, будто нужно понять весь стек сразу: какие переменные обязательны, зачем нужен `/system`, и почему один и тот же параметр может встретиться в шаблоне дважды.

## What Changes

- Убрать дубли и неоднозначные подсказки из `desengine.config-example.txt`.
- Сжать канонический install-flow до короткого первого маршрута без потери ссылок на профильные документы.
- Явно объяснить, что `/system` и ручное обновление onboarding нужны как repair path, а не как обязательный первый шаг "на всякий случай".
- Синхронизировать `README.md`, `INSTALL.md` и связанные `docs/**`, чтобы первый запуск и onboarding-flow описывались одинаково.

## Capabilities

### Modified Capabilities

- `external-local-onboarding`: канонические инструкции первого запуска должны одинаково объяснять первичную синхронизацию `/onboarding`, repair path через `/system` и разделение ролей администратора и пользователя.

## Impact

- Первый локальный запуск становится короче и понятнее без изменения runtime-механики.
- Документационная карта больше не отправляет читателя по битым относительным ссылкам в профильных инструкциях.
