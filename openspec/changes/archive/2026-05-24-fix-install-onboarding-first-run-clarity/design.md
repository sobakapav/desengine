## Контекст

- `dispatcher-doc` задаёт общий контур документации, но сам fix должен реализовать исполнительский срез без пересмотра runtime-решений.
- Спеки `external-local-onboarding` и `onboarding-repo` уже фиксируют, что `/onboarding` синхронизируется из `ONBOARDING_REPO_URL`, а `/system` остаётся явным способом повторной синхронизации.

## Решение

1. Свести первый запуск к короткому маршруту "создать конфиг -> выбрать одного LLM-провайдера -> запустить dev-server", а расширенные детали оставить в профильных docs.
2. Убрать путающий дубль `SANDPACK_UI_KIT` из шаблона конфигурации и добавить явную подсказку, что на первом проходе остальные настройки можно не трогать.
3. Синхронизировать канонические документы так, чтобы они одинаково описывали автоматическую первичную синхронизацию `/onboarding` и ручной repair path через `/system`.
4. Исправить относительные ссылки в профильных docs, чтобы человек реально мог идти по карте документации, а не угадывать путь вручную.
