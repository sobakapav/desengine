## Why

Project contract уже живёт в runtime, storage, task actions и Workbench, но для пользователя проект как самостоятельная сущность почти не существует. Сейчас весь project-aware UX спрятан внутри конкретной задачи, из-за чего:

- пользователь не видит, что у продукта вообще есть отдельные проекты;
- невозможно открыть список проектов как отдельную рабочую поверхность;
- невозможно зайти в конкретный проект как в точку входа для настройки и дальнейшей работы;
- project registry остаётся технической деталью Workbench, а не пользовательской частью продукта.

## What Changes

- Добавить в верхнее меню вкладку `Проекты` рядом с уже существующими user-facing разделами.
- Ввести project navigation helpers и canonical routes:
  - `/projects`;
  - `/projects/[projectId]`.
- Поднять отдельный page/screen слой для:
  - списка проектов с active-project сигналом;
  - страницы конкретного проекта с базовой metadata-сводкой и точкой входа в его настройку.
- Использовать существующий project registry как source of truth и не дублировать второй project shape вне canonical project boundary.
- Зафиксировать user-facing contract в OpenSpec capability `projects`.

## Impact

- Проекты впервые становятся видимой частью пользовательского продукта, а не только внутренним runtime-контекстом.
- Следующие project-facing changes смогут опираться на отдельный раздел `/projects`, а не встраивать всё в Workbench конкретной задачи.
