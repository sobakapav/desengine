## Термины

- **Инспектор** — UI-компонент, который отображает изображение и позволяет выполнять интерактивные действия (зум/пан/оверлеи) и экспортировать структурированные результаты.
- **Аннотация/Оверлей** — примитив (точка/прямоугольник/линия/полилиния), заданный в координатах исходного изображения.

## Дизайн: Konva слой

### Библиотеки

- `konva` + `react-konva`.

### Компоненты (предложение)

- `KonvaImageInspector` (минимальный инспектор)
  - props (черновик):
    - `src`
    - `knownNaturalWidth?`, `knownNaturalHeight?` (если известны заранее, например из `level.images`)
    - `onMetaReady?(meta)` — сообщает наружу метаданные, как только они определились
    - `onViewChange?(view)` — (опционально, позже) сообщает наружу текущий viewport (scale/offset), если понадобится
  - на первом этапе **не требует** `initialState` и **не экспортирует** overlays/аннотации.
- `ImageInspectorDialog` / `ImageInspectorPanel`
  - оболочка (диалог/панель), кнопки «экспорт», «копировать JSON», «сброс», «fit».
  - на первом этапе достаточно «Скопировать метаданные» (или «Скопировать JSON») + управление view.

### Слои Konva

- `Stage`
  - управляет viewport-трансформацией (scale + translation) для зума/пана;
  - принимает события мыши/тача.
- `Layer: image`
  - `Konva.Image` с загруженным изображением.
- `Layer: overlays`
  - `Rect`/`Circle`/`Line`/`Text` и др.
- (опционально) `Layer: ui`
  - курсор/подсказки/временные примитивы в режиме рисования.

### Координаты и трансформации

Ключевой принцип: **все экспортируемые примитивы живут в координатах исходного изображения** (image space), независимо от текущего зума/пана.

Нужны утилиты:
- `screenToImage(point)` и `imageToScreen(point)` на базе текущей матрицы трансформации Konva.
- нормализация/квантизация координат (например, округление до 0.5px или 1px по требованию).

## Контракт данных инспектора

### `ImageInspectorMeta` (минимум на первом этапе)

- `version`: строка (например, `"1"`) для совместимости.
- `image`:
  - `src` (как идентификатор источника; не обязательно внешний URL)
  - `naturalWidth`, `naturalHeight` (нативные размеры, линейные)
  - (опционально) `aspectRatio`

Требование: `onMetaReady(meta)` вызывается **без искусственных задержек** сразу после того, как метаданные доступны.

Источники метаданных:
- приоритет 1: `knownNaturalWidth/knownNaturalHeight`, если они уже известны из конфигурации уровня/задачи;
- приоритет 2: загрузка изображения в браузере (`HTMLImageElement`) и чтение `naturalWidth/naturalHeight` по `onload`.

### Экспорт «наружу» (минимум)

Минимальный набор:
- копирование JSON в буфер (UI action);
- callback `onMetaReady(meta)` для интеграции с остальными частями UI;
- (опционально) кнопка «Скачать JSON» как файл.

Если нужен серверный экспорт/обмен:
- отдельный API endpoint (например, `POST /api/.../image-inspector/export`) будет добавлен только после уточнения сценариев и требований по хранению/безопасности.

## Нефункциональные требования

- Производительность: большие изображения не должны «убивать» UI; зум/пан должен быть плавным.
- Accessibility: клавиатурные шорткаты для базовых действий (зум/reset) и доступность панели управления.
- Безопасность: `src` и загрузка изображений остаются в рамках текущих ограничений (не расширяем доступ без явного требования).

## Открытые вопросы

- Что именно означает «анализ картинки» в рамках инспектора (минимум: метаданные `naturalWidth/naturalHeight`; дальше: инструмент измерения? выбор цвета? расчёт площади? OCR?).
- Какие данные и куда именно нужно «отдавать наружу» (в код как объект, в API, в файл, в clipboard)?
- Требуется ли сохранение состояния инспектора между сессиями/перезагрузками (и где хранить: localStorage, сервер, файл в task)?
- На первом этапе берём **самый простой вариант**: наружу отдаём только `ImageInspectorMeta` (в первую очередь `naturalWidth/naturalHeight`). `view`/viewport добавляем только если появится конкретная потребность.
