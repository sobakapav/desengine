## Why

После `npm run dev` пользователь видит предупреждение Next.js о том, что workspace root определён неверно: runtime выбирает внешний каталог из-за нескольких `package-lock.json`, хотя приложение запущено из корректной папки проекта.

Из пользовательского отчёта следует конкретный симптом:

- Next.js выбирает `/Users/arinabajgildina/package-lock.json` как root вместо каталога приложения;
- предупреждение исчезает после ручной правки `next.config.ts` с `turbopack.root = __dirname`;
- без этой правки install/dev опыт выглядит недетерминированным и вызывает недоверие к локальному setup ещё до работы с задачами.

## What Changes

- Зафиксировать в конфигурации приложения канонический root для Turbopack/Next dev.
- Убрать ложное предупреждение о неверном workspace root в сценарии, когда рядом существуют посторонние lockfile.
- Добавить guardrail, чтобы регресс root-detection не возвращался после следующих правок `next.config.ts`.

## Non-goals

- Не менять Node.js, Next.js или Turbopack как install-critical стек.
- Не чинить unrelated runtime/performance проблемы, если они не связаны с root-detection warning.
- Не перекладывать решение на ручные локальные инструкции для пользователя вместо репозиторного конфигурационного fix.

## Impact

- Локальный запуск `npm run dev` перестанет пугать пользователя ложной диагностикой workspace root.
- Install/onboarding контур станет детерминированнее в окружениях, где рядом лежат дополнительные lockfile.
