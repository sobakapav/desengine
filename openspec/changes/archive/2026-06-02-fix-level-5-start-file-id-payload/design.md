## Context

Сейчас start-flow выполняет три шага подряд:

1. получает structured JSON от LLM;
2. нормализует его через `normalizeStartPayload(...)`;
3. валидирует через `validateGeneratedFilesPayload(...)`.

Проблема в том, что нормализация чинит только пустые строки и только для части файлов. Если модель возвращает `component` или `Component.tsx` вместо кода, payload доходит до validator почти без изменений и падает как на некорректном содержимом файла.

## Goals

- Не допускать падения initiator-start на очевидном placeholder-ответе модели.
- Сохранить строгий validator, не превращая его в “проглоти всё”.
- Гарантировать, что обязательные стартовые файлы получают валидный минимальный scaffold, если реального содержимого нет.

## Non-goals

- Менять поведение iterate/check.
- Ослаблять требования к `Component.tsx` как к default-export React component.
- Вводить новый общий runtime для автогенерации файлов.

## Decisions

### Placeholder file-id трактуется как отсутствие содержимого

Если start payload возвращает для файла строку, равную `file.id` или `file.fileName`, система трактует это не как валидный контент, а как пустой placeholder.

### Приоритет восстановления

Для start-flow восстановление идёт в таком порядке:

1. существующее содержимое файла из текущего task state;
2. встроенный scaffold для стартового файла;
3. исходное значение только если для файла нет ни текущего содержимого, ни scaffold.

### Safe scaffold для обязательных стартовых файлов

Встроенные fallback-значения нужны не только для `styles.ts` / `mock.ts` / `props.ts`, но и для обязательных стартовых файлов:

- `Component.tsx` получает минимальный валидный default-export React component;
- `Component.stories.ts` получает минимальный story scaffold, ссылающийся на `Component`.

## Risks

- Слишком агрессивное repair-поведение может скрыть систематическую деградацию prompts/model output.
- Неправильный scaffold может сохранить формально валидный, но практически бесполезный стартовый набор.

## Trade-offs

- Выбран локальный repair-path вместо ослабления validator: это сохраняет строгую защиту для iterate/check и чинит сбой на том слое, где он возникает.
- Мы принимаем минимальный scaffold как fallback, хотя он беднее желаемого ответа модели, потому что это лучше, чем полный срыв старта уровня.

## Open Questions

- Нужно ли позже поднимать отдельный telemetry/diagnostic signal на такие repaired start responses, чтобы видеть частоту деградации модели.
