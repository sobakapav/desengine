## Why

Сейчас Sandpack preview умеет работать с ограниченным набором UI-зависимостей и правил резолва импорта (включая `@/components/ui/*`). Это хорошо для базового потока, но плохо масштабируется, когда нужно:

- быстро попробовать другой UI kit (например, Mantine/MUI/Ant Design) без правок в runtime-коде;
- переиспользовать один и тот же Sandpack wiring, но с разными dependency-наборами и bootstrap-обвязкой;
- добавлять новые UI kit'ы безопасно и ревьюопригодно (изменениями в отдельной конфигурации, а не через условную логику по всему preview builder).

Нужно выделить слой «адаптеров к Sandpack», который подключает разные UI kit'ы через внешнюю конфигурацию и npm-зависимости.

## What Changes

- Вводим понятие **Sandpack UI kit adapter**: модуль, который описывает, какие npm-пакеты, файлы и bootstrap-настройки должны быть добавлены в виртуальный проект Sandpack для конкретного UI kit'а.
- Вынесем список поддерживаемых UI kit'ов и их параметры во **внешний конфигурационный файл** (добавление/изменение kit'ов должно происходить через правку этого файла).
- Обновим сборку Sandpack payload так, чтобы она могла применить выбранный adapter к payload перед запуском preview.
- Зафиксируем контракт выбора kit'а (откуда берётся `uiKitId`, какие значения допустимы, какой fallback применяется).

## Capabilities

### Modified Capabilities
- `task`: Sandpack preview получает расширяемый слой поддержки UI kit'ов (через adapters), при этом базовые сценарии preview остаются совместимыми.
- `level-labs`: лаборатория уровня получает возможность (явно или косвенно) выбирать UI kit для preview-окружения через контракт уровня/задачи.

## Impact

- Появится новый внешний конфиг (в репозитории), который является единственным источником правды по поддерживаемым UI kit'ам для Sandpack.
- Runtime-код Sandpack preview станет проще: он будет применять выбранный adapter вместо роста условной логики.
- Потребуются тесты (unit + traceability), чтобы гарантировать стабильность резолва adapter'ов и их применения к payload.
