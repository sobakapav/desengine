- Что меняется для пользователя: журнал релиза теперь пополняется автоматически при закрытии change, поэтому важные изменения меньше шансов потерять между реализацией и выпуском.
- Как это влияет на пользователя: по `release-notes.md` будет проще понять, что реально доехало до релиза и как проверить каждое изменение без чтения внутренних proposal и task-файлов.
- Как проверить:
  1. Закрыть release-linked implement или fix через `npm run os:close -- <change>`.
  2. Открыть `openspec/changes/release-2026-06-02-quality/release-notes.md`.
  3. Убедиться, что у закрытого change появилась отдельная запись с простым описанием и шагами ручной проверки.
