## Контекст

В проекте уже есть единый конфиг Sandpack UI kit'ов и логика сборки preview payload. Для shadcn-контура это означает, что runtime должен не только разрешать импорты вида `@/components/ui/*`, но и поднимать все транзитивные пакеты и локальные UI-файлы, без которых конкретный компонент не может собраться в виртуальном проекте.

Сейчас эта гарантия неполная: часть компонентов проходит, а часть пришлось временно исключить из `components/ui/index.ts`. Это указывает не на пользовательскую ошибку, а на пробел в описании dependency graph для Sandpack preview.

## Цели

- Вернуть 11 исключённых shadcn-компонентов в поддерживаемый preview surface.
- Сделать зависимостный контракт Sandpack достаточно явным, чтобы runtime распознавал эти компоненты как допустимые без ручного выпиливания из индекса.
- Удержать честную диагностику: компонент считается поддерживаемым только если для него действительно хватает runtime-зависимостей и связанных source files.

## Non-goals

- Не объявлять весь каталог `components/ui` автоматически поддерживаемым без фактической проверки.
- Не подменять dependency resolution жёстким allowlist'ом имён компонентов без понимания их транзитивных требований.
- Не затрагивать unrelated preview defects, если они не мешают именно dependency-resolution для этих 11 компонентов.

## Направление реализации

1. Зафиксировать для каждого из 11 компонентов, какие именно внешние пакеты и локальные `components/ui/*` файлы требуются Sandpack runtime.
2. Дополнить shadcn-конфиг и/или связанный preview builder так, чтобы runtime заранее получал эти зависимости в виртуальном проекте.
3. Вернуть компоненты в экспортный surface только после того, как unit-слой докажет их распознавание и отсутствие ложной ошибки `Неподдерживаемая зависимость`.

## Риски и компромиссы

- Если добавить только npm-пакеты, но не учесть локальные UI-зависимости между компонентами, дефект останется частично скрытым.
- Если без разбора открыть все компоненты обратно, preview может перейти от controlled fallback к runtime-crash в iframe.
- Компоненты вроде `chart`, `sidebar` и `sonner` могут требовать не только пакеты, но и набор связанных source files; это нужно считать частью одного runtime-контракта, а не побочным случаем.
