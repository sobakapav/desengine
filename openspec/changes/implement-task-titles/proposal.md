## Why

Сейчас task-контур опирается в основном на `taskId` и технический `config.json`. В `lib/task/schema.ts` и `lib/task/types.ts` у задачи нет отдельного поля `title`, поэтому пользовательские поверхности и связанные task hints не получают стабильное человекочитаемое имя задачи и вынуждены либо показывать slug, либо обходиться без названия.

Для onboarding это ухудшает читаемость: пользователю сложнее понять, над какой задачей он работает, а более широкая task-система теряет часть объясняющей ценности.

## What Changes

- Ввести явное название задачи в content/runtime-контракт задачи.
- Протянуть это название через task catalog, `TaskListItem` и связанные task-экраны, где сейчас показывается только `taskId` или отсутствует название.
- При необходимости передать название в task-hints/prompt-context слой, если именно он используется как источник пользовательской подсказки.
- Зафиксировать поведенческий контракт и тестовую рамку для нового поля, чтобы downstream changes не возвращались к техническим slug как к user-facing имени.

## Non-goals

- Не переименовывать сами `taskId`, каталоги `onboarding/tasks/*` или файловую структуру задач.
- Не менять названия уровней и не пересобирать общую информационную архитектуру onboarding.
- Не вводить отдельный поиск, теги или новую taxonomy-систему поверх задач.

## Capabilities

### Modified Capabilities

- `task`: задача получает user-facing название как часть наблюдаемого контракта.
- `level-labs`: рабочий экран и связанные task-поверхности могут показывать пользователю название текущей задачи вместо одного только `taskId`.
- `prompt-context`: затрагивается только если название задачи становится частью данных для task hints templating.

## Acceptance Criteria

- У задачи появляется единый source of truth для человекочитаемого названия.
- Runtime-модель задачи и хотя бы одна пользовательская task-поверхность читают это название без вывода из slug.
- Если название попадает в task hints templating, это явно отражено в OpenSpec capability и traceability.
- В `tasks.md` зафиксированы уровни проверки, команды запуска и fixture-данные для нового контракта.
