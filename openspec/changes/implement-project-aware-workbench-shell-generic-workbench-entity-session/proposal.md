## Why

Сущность верстака уже заявлена в продуктовой линии, но пока почти не материализована в активном контракте системы.

Сейчас пользователь видит проект, компоненты и workflow, но не видит сам Workbench как понятную рабочую сущность, связующую:

- проект как основной контекст работы;
- workflow как направляющий процесс;
- subject как конкретный предмет проработки.

Из-за этого верстак остаётся слишком абстрактным:

- архитектурное решение не даёт пользователю новой ценности;
- future-слой инструментов и пространств рискует снова расползтись по ad-hoc поверхностям;
- переход от project/workflow к реальной рабочей среде не имеет прозрачного промежуточного контракта.

На этом этапе не нужно открывать полноценную работу на верстаке и не нужно вводить типологию верстаков. Нужно сделать более простой и полезный шаг: материализовать generic project-aware workbench shell, который уже виден пользователю, привязан к проекту и workflow, но честно работает в locked-режиме.

## What Changes

- Заполнить OpenSpec-контур для materialized workbench shell как первой пользовательски наблюдаемой формы верстака.
- Зафиксировать active capability `workbench` с минимальным продуктовым контрактом:
  - generic `WorkbenchDefinition` без ранней типологии;
  - `WorkbenchSession`, привязанную к `project`, `workflow` и `subject`;
  - locked-режим без допуска к редактированию, запуску инструментов и выпуску результатов.
- Закрепить, что project surface может материализовать и открывать workbench shell как часть работы над проектом.
- Закрепить, что workflow может публиковать workbench shell для project-owned subject, не возвращая task-модель в пользовательский путь.
- Не вводить реальные tool flows, типы верстаков и рабочие сценарии внутри workbench в этой волне.

## Impact

- В продуктовой архитектуре появляется понятный bridge между проектом, workflow и будущей рабочей поверхностью.
- Workbench начинает нести пользовательскую ценность уже как наблюдаемая и объяснимая сущность, а не только как внутренняя идея.
- Следующая волна foundation/UI-реализации получает простой контракт без преждевременной детализации по типам верстаков.
