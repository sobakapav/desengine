## Контекст

Workbench уже содержит почти все нужные данные, но их spatial arrangement мешает чтению:
- контекст задачи отделён от зоны редактирования и уходит ниже fold;
- preview и код забирают много высоты;
- при multi-file шагах интерфейс не акцентирует переход от одного файла к нескольким.

Проблема здесь не в отсутствии данных, а в их плохой видимости и неудачной иерархии внимания.

## Решение

1. Зафиксировать compact context block для рабочего экрана:
   - краткое task-specific пояснение;
   - доступ к полному описанию без возврата к отдельному preview state;
   - заметный статус текущего уровня и файлов.
2. Пересобрать vertical layout так, чтобы:
   - preview и код были доступны в первом экране;
   - важный текстовый контекст не терялся;
   - лишний вертикальный шум уменьшился.
3. Для появления новых файлов уровня добавить явный affordance:
   - badge/new marker;
   - автофокус/первое выделение;
   - либо заметное текстовое уведомление.

## Проверочный слой

- Затронутые capability/scenario:
  - `level-labs` / рабочий экран задачи;
  - `task` / устойчивость preview и кода в рамках одного рабочего пространства;
  - `component-file-set` / многофайловый режим уровня.
- Уровень проверки: `component/browser`.
- Команда: `npm run test:e2e -- test/e2e/workbench-context-visibility.spec.ts`

Итоговая проверка должна доказывать именно пользовательскую видимость контекста, а не только наличие соответствующих React-компонентов в дереве.
