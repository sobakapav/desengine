## Why

В документе есть группа связанных UX-жалоб:
- описание задачи в “превью” и в открытой задаче воспринимается как разное по масштабу и удобству;
- layout рабочего экрана слишком длинный, приходится постоянно скроллить;
- на уровне 3 пользователь не заметил, что создался `styles.ts`, потому что файл оказался вне зоны внимания.

Source-level картина это подтверждает:
- [WorkbenchView.tsx](/Users/op/dev/sobakapav/desengine/components/desengine/lab/Workbench/WorkbenchView.tsx) складывает preview, task tip, редактор и prompt history в длинную вертикальную колонку;
- ключевой task context в рабочем экране легко уходит за пределы viewport;
- многофайловый режим не даёт достаточно сильного сигнала, что появился новый важный файл уровня.

Для пользователя это выглядит как потеря контекста внутри задачи: система вроде даёт нужную информацию, но прячет её в layout.

## What Changes

- Пересобрать Workbench так, чтобы основной контекст задачи и рабочие файлы были видны без постоянного скролла.
- Выровнять presentation task description между входом в задачу и рабочим экраном.
- Сделать появление второго/нового файла уровня явно заметным.

## Non-goals

- Не делать полный redesign всей лаборатории.
- Не менять didactic content самих задач.
- Не смешивать этот UX-fix с preview runtime или hidden check.

## Impact

- Пользователь сможет быстрее восстановить контекст после паузы.
- Меньше шансов пропустить новый файл уровня или важное task-specific пояснение.
