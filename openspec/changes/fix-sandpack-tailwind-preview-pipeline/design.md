## Контекст

Текущий payload builder уже собирает виртуальный Sandpack project с `styles.css`, `tailwind.config.js` и `postcss.config.js`, а host проверяет применение стилей через runtime probe. Проблема в том, что этот контракт сейчас может дойти до состояния `unstyled-dom`: React-дерево уже смонтировано, но utility-классы не материализовались в iframe CSS.

## Гипотеза дизайна

Нужно чинить не host-диагностику, а сам CSS pipeline preview-runtime. Исправление принимается только если живой iframe получает те стили, которые ожидает probe и пользовательский компонент.

## Направление реализации

1. Локализовать точку разрыва между собранным payload и фактическим CSS внутри Sandpack iframe.
2. Сделать style pipeline детерминированным для preview:
   - либо через корректную сборку Tailwind/CSS до передачи в Sandpack,
   - либо через другой эквивалентный runtime path, который гарантирует те же utility-стили без деградации пользовательского опыта.
3. Сохранить host contract:
   - `ready` только когда стили реально применились;
   - `unstyled-dom` только как честная диагностика реального CSS failure;
   - `render-error` только для настоящего runtime/crash path.

## Ограничения

- Нельзя закрывать defect подменой style contract на более слабый.
- Нельзя объявлять success, если preview рендерит только текст/DOM без подтверждённых utility-стилей.
- Проверка должна остаться браузерной, потому что unit-слой сам по себе не доказывает применение CSS внутри iframe.
