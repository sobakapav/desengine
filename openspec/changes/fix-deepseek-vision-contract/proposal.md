## Why

В текущей локальной конфигурации активный provider — `deepseek`. При этом task runtime строит `start`, `iterate` и `check` как image-dependent сценарии: по OpenSpec они обязаны отправлять все разрешённые картинки уровня.

Фактическая реализация расходится с этим контрактом: `lib/llm/providers/deepseek.ts` не передаёт `imageBase64List` в provider request, а добавляет текстовую оговорку, что изображения недоступны. Для пользователя это означает, что уточняющий запрос уходит “не туда”: он формулирует изменения по картинке, а модель отвечает без визуального контекста.

## What Changes

- Устранить silent-loss изображений в DeepSeek task-flow.
- Ввести корректное поведение для image-bearing запросов:
  - либо DeepSeek действительно получает изображения в поддерживаемом формате;
  - либо runtime и диагностика fail-fast останавливают `start`/`iterate`/`check` до запроса, если активная DeepSeek-конфигурация не поддерживает vision.
- Добавить покрытие, которое не позволит снова принять image-bearing запрос и тихо превратить его в text-only.

## Non-goals

- Не менять product contract итерации.
- Не переводить всю систему на другого провайдера по умолчанию.
- Не перерабатывать prompts или task workflow вне image-delivery boundary.

## Impact

- Уточняющие запросы и проверка уровня перестанут silently работать без визуального контекста.
- Пользователь либо получает корректный multimodal вызов, либо понятный ранний отказ с actionable диагностикой.
