## Контекст

- Родительский change управляет приоритетом и порядком реализации.
- Пользователь явно потребовал забыть `Task` как продуктовую сущность и вернуть работу на уровень проекта.

## Решение

1. Страница проекта становится главной рабочей поверхностью.
   Она больше не показывает task-binding panel и не запускает работу через `postTaskStart` / `getLabUrl`.

2. Вводится project-owned session слой в browser-local storage.
   Этот слой хранит:
   - статус работы над проектом;
   - текущий фокус проекта;
   - историю project-level событий;
   - наблюдаемую картину project workflow.

3. `ProjectComponent` остаётся частью проекта, а не отдельной точкой входа.
   Пользователь:
   - добавляет компонент в проект;
   - делает его текущим фокусом проекта;
   - отмечает его как готовый внутри проекта;
   - при необходимости возвращает его в активную работу проекта.

4. Project workflow становится explainability-слоем проекта.
   Он показывает:
   - этапы project-workflow;
   - текущий фокус;
   - положение каждого компонента внутри проектной работы.

5. Legacy index routes `/tasks` и `/lab` остаются только как redirect в `/projects`.

## Компромиссы

- В этом change task runtime не удаляется из репозитория целиком.
  Он перестаёт быть user-facing и перестаёт определять project path, но legacy technical surface ещё существует для старых route и модулей.
- Workbench не переизобретается как отдельный project page внутри этой волны.
  Вместо этого project page получает собственный project-first workspace layer.
