# Change: producer-ui-kit

## Зачем

Нужен отдельный верхнеуровневый исследовательский поток по направлению UI kit, чтобы диспетчерские и fix/implement changes опирались на единый корневой контекст, а не были вложены в feature-фокус.

## Что меняется

- `producer-ui-kit` закрепляется под стратегическим фокусом `focus-features`.
- `producer-ui-kit` хранит память о кандидатах на подключение и о продуктовых условиях их допуска, но не порождает преждевременные `implement`-ветки.
- Диспетчерская и внедренческая ветка UI kit ведётся отдельно в feature-контуре (`focus-features`) только после того, как producer определит:
  - какой kit действительно нужен;
  - в каком сценарии он нужен;
  - по каким критериям его стоит подключать именно сейчас.

## Кандидаты, которые producer должен помнить

- `align-ui`
- `base-ui`
- `chakra-ui`
- `heroui`
- `mantine`
- `primereact`
- `radix-ui`
- `react-aria`
- `reshaped`

Пока это не backlog немедленного подключения, а список kit'ов, для которых producer должен держать в уме:
- совместимость с моделью project-level переключения;
- требуемые зависимости и bootstrap;
- ожидаемую продуктовую ценность;
- момент, когда подключение становится оправданным.
