## Why

Пользовательские проекты часто уже существуют в Figma: дизайн-система, экраны, компоненты, токены, иконки. Чтобы desengine стал инструментом работы, нужен путь «из внешнего источника → в проект внутри системы».

Адаптер импорта Figma должен:

- забирать Figma-проект и превращать его в `Project` внутри desengine;
- сохранять исходные артефакты и метаданные (чтобы можно было продолжать работу);
- стать базой для дальнейших интеграций (синхронизация, обновления, преобразования в код/DS).

Технические требования пока неизвестны — это нормальная стадия. Но change нужен уже сейчас, чтобы зафиксировать направление, контракт и план.

## Зависимости

Этот change зависит от `producer-project`, потому что импорт должен создавать и наполнять project-scoped данные и вписываться в актуальный project-контур системы.

## What Changes

Этот change плановый/исследовательский. Результат:

- определение контракта **Figma Import Adapter**:
  - какие входы (file key, node ids, pages, mode);
  - какие выходы (Project + artifacts);
  - какая гранулярность (весь проект, выбранные страницы/фреймы).
- модель артефактов, которые сохраняем (MVP):
  - структура страниц/фреймов (как дерево);
  - компоненты/варианты (если доступны);
  - стили/токены (цвета, типографика, spacing — как минимум ссылка/снимок);
  - ассеты (иконки/изображения) — как ссылки или экспортированные файлы (определить).
- внутри этой линии отдельно удерживаются как части одного import/scaffold-направления:
  - конвертация Figma-компонента в базовый React-компонент;
  - перевод структуры экранов и страниц в кодовое представление;
  - извлечение иерархии компонент из неидеально организованного Figma-материала;
  - импорт Figma-проекта в кодовую заготовку для дальнейшей доработки, без обещания визуально точного результата.
- политика доступа и приватности:
  - ключи/токены доступа принадлежат пользователю;
  - хранение секретов безопасно;
  - возможность удалить импортированные данные.
- roadmap на реализацию по этапам + тестовый план/traceability.

## Non-goals

- Полная двусторонняя синхронизация с Figma (позже).
- Идеальная генерация кода из Figma «в один клик» (позже).

## Capabilities

### New Capabilities
- `import-figma`: импорт Figma в проект.

### Modified Capabilities
- `projects`: появляется источник данных «импорт».
- `design-system` / `assets` (если вводятся): получают входной канал из Figma.

## Acceptance Criteria

- Описан контракт импорта (inputs/outputs/ограничения).
- Описан MVP набор сохраняемых артефактов.
- Описан план безопасности и владения данными пользователем.
- Есть roadmap на отдельные changes и тестовый план/traceability.
