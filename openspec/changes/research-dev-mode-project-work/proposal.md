## Why

desengine должен стать инструментом для работы над реальными проектами, а не только образовательной платформой. Для этого нужно уже сейчас начать:

- разделять пользовательскую активность на **проекты**;
- позволять работать **внутри выбранного проекта** над разными задачами;
- хранить и применять **настройки и данные на уровне проекта** (а не «глобально на пользователя/сессию»).

Это вводит «режим разработки» — контур, где пользователь не «учится», а делает работу над конкретным проектом.

## Зависимости

Этот change развивает тему проекта и зависит от релизного среза `dispatcher-ui-kit` (минимальный контракт проекта и привязка UI-настроек к проекту).

## What Changes

- Вводим режим приложения **Development Mode** (режим разработки) как основной сценарий «работа над проектом».
- Добавляем первичную модель **Project Workspace**:
  - список проектов пользователя;
  - выбор активного проекта;
  - область данных проекта (project-scoped data).
- Переносим ключевую пользовательскую активность из «глобальной» области в проектную:
  - настройка UI kit/режима UI (уже начинается в базовом change);
  - данные задач/артефактов/истории, которые логически относятся к конкретному проекту.
- Добавляем базовые операции:
  - создать проект;
  - открыть/выбрать проект;
  - переименовать/удалить проект (если допустимо);
  - сменить активный проект без перезагрузки.

## Non-goals

- Многопользовательские проекты, доступы/роли, совместная работа — отдельные changes.
- Полная миграция всех доменов в project-scoped модель за один раз (делаем поэтапно).
- Перенос/унификация дизайн-токенов между UI kit'ами (отдельный большой change).

## Capabilities

### New Capabilities
- `projects`: управление проектами и рабочими пространствами.
- `dev-mode`: режим разработки как основной контур работы.

### Modified Capabilities
- `task`: задачи и их данные начинают иметь привязку к проекту.
- `level-labs`: лаборатория работает в контексте активного проекта (настройки/данные проектные).

## Acceptance Criteria

- Пользователь может создать проект и выбрать его как активный (без перезагрузки страницы).
- Активный проект влияет на данные и настройки: изменения в одном проекте не «протекают» в другой.
- Есть минимальная тестовая опора (unit + traceability; при необходимости e2e smoke), которая доказывает project-scoping.
- Зафиксирован план миграции: какие домены уже project-scoped, какие пока остаются глобальными, и почему.
