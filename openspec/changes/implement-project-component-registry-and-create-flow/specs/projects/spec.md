## MODIFIED Requirements

### Requirement: Проекты доступны как самостоятельный пользовательский раздел

Система SHALL позволять не только открывать project registry, но и создавать новые проекты прямо из canonical раздела `/projects`.

#### Scenario: Пользователь создаёт новый проект из project registry
- **WHEN** пользователь открывает `/projects`
- **AND** вводит имя нового проекта
- **THEN** система создаёт новый `ProjectWorkspace` в canonical project registry
- **AND** пользователь сразу видит этот проект в списке раздела `Проекты`

### Requirement: Проект является контейнером для пользовательских компонентов

Система SHALL показывать на странице проекта собственные компоненты проекта как отдельные сущности, из которых затем может стартовать workflow-работа.

#### Scenario: Пользователь видит список компонентов проекта
- **WHEN** пользователь открывает `/projects/<projectId>`
- **THEN** система показывает список компонентов, принадлежащих этому проекту
- **AND** компонент читается как самостоятельная project-scoped сущность, а не как скрытый хвост legacy runtime

#### Scenario: Пользователь создаёт компонент внутри проекта
- **WHEN** пользователь открывает `/projects/<projectId>`
- **AND** вводит имя нового компонента
- **THEN** система создаёт `ProjectComponent`, связанный с этим `ProjectWorkspace`
- **AND** по умолчанию фиксирует для него workflow `image-to-component-workflow`
- **AND** новый компонент сразу появляется в списке компонентов проекта
