## Контекст

- `test:live` сейчас реализован через `tools/testing/pending-layer.mjs live`.
- В репозитории уже есть `test/helpers/test-env.ts`, который умеет:
  - читать provider-specific env;
  - возвращать список отсутствующих переменных;
  - печатать диагностику без раскрытия секретов.
- `openspec/specs/testing-layer/spec.md` уже требует понятный live/provider запуск с чтением credentials из env и диагностикой отсутствующих значений.

## Решение

- Заменить placeholder `test:live` на минимальный preflight-скрипт.
- Preflight должен:
  - определить текущий provider;
  - проверить только разрешённый набор env-переменных;
  - вернуть понятную диагностику, если чего-то не хватает;
  - не выполнять сетевой вызов и не менять пользовательские данные.
- Дополнить unit-покрытие на этот preflight и обновить документацию `docs/testing-layer.md` и `test/README.md`.

## Риски и компромиссы

- Риск: команда будет восприниматься как полноценный live-test, хотя это пока только preflight.
  - Митигация: явно маркировать режим как preflight и документировать, что реальный provider-call остаётся следующим этапом.

- Риск: случайно расширить обязательный слой за счёт live-зависимостей.
  - Митигация: не менять `test:full` и не добавлять скрытых сетевых вызовов.
