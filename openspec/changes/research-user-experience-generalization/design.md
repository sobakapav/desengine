## Термины

- **Experience Event**: единица журнала (например: prompt-run, error, code-variant, decision).
- **Experiment**: связанная серия событий, ведущая к результату (артефактам/решению).
- **Skill**: воспроизводимый набор инструкций/практик, который можно применять в будущем.

## Минимальный контракт данных (MVP)

Предлагаемый базовый формат:

- `ExperienceEvent`:
  - `id`
  - `createdAt`
  - `projectId?`
  - `taskId?` / `sessionId?`
  - `type` (например: `prompt`, `response`, `error`, `patch`, `note`)
  - `payload` (структурированный JSON с ограниченным размером)
  - `tags` (строки)
  - `links` (ссылки на связанные события/файлы)

И отдельный «контейнер»:

- `Experiment`:
  - `id`
  - `title`
  - `eventIds[]`
  - `outcome` (краткий итог)

## Хранилище и приватность

MVP:

- локальное хранилище в проекте пользователя/в браузере (в зависимости от текущей архитектуры);
- явное управление пользователем: включить/выключить сбор, удалить данные, экспортировать.

Важно:

- не логировать секреты по умолчанию;
- предусмотреть redaction (маскирование) и size limits.

## Synthesize → Skill

Минимальный pipeline:

1) Пользователь выбирает эксперимент/набор событий.
2) Система формирует «черновик навыка»:
   - цель
   - входы/выходы
   - пошаговый процесс
   - ошибки/антипаттерны
   - примеры промптов/кодовых решений
3) Пользователь подтверждает и сохраняет артефакт:
   - `Skill` (в формате, совместимом с текущей системой навыков/skills).

## Тестирование

- Unit/contract: валидация схемы событий, лимиты, redaction.
- Traceability: есть связь сценариев experience ↔ тестов.
- (опционально) E2E smoke: запись события → выбор набора → создание навыка.
