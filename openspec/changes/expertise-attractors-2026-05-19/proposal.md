## Why

По мере накопления опыта в системе должны появляться «точки концентрации» — повторяемые паттерны работы, которые уже достаточно раз были сделаны, чтобы их можно было:

- обобщить,
- упаковать,
- назвать,
- повторно применять.

Условные названия: **навыки**, **атомы**, **суперсилы**. Это не конкретная фича «на завтра», а стратегическое направление, которое нельзя потерять и которое должно быть связано с системой накопления/обобщения опыта.

## Зависимости

Этот change зависит от `user-experience-generalization-2026-05-19`, потому что без накопленных данных невозможно выявлять повторяемость и формировать устойчивые аттракторы.

## What Changes

Этот change — vision/research. Результат:

- определение сущности **Expertise Attractor** (навык/атом/суперсила) и её жизненного цикла;
- критерии «когда что-то становится аттрактором» (сигналы повторяемости, ценность, воспроизводимость);
- механика выявления кандидатов:
  - на базе журналов опыта (events/experiments);
  - через ручные пометки пользователя (important/reusable);
  - через метрики (частота, успех/неуспех, экономия времени).
- механика упаковки:
  - в skill (инструкции/шаблоны/чеклисты/пакеты артефактов);
  - в инструмент/шаблон workflow (если релевантно).
- план внедрения по этапам (будущие changes) и тестовый план.

## Non-goals

- Автоматическое «волшебное» выделение суперсил без участия пользователя.
- Командный knowledge base (пока только персональный слой).

## Capabilities

### New Capabilities
- `attractors`: управление аттракторами экспертизы (каталог, версии, применение).

### Modified Capabilities
- `experience`: опыт становится источником данных для выявления аттракторов.
- `skill-synthesis`: синтез навыков расширяется до «упаковки аттрактора».

## Acceptance Criteria

- Есть чёткое определение сущности аттрактора и её артефактов (что хранится, как версионируется).
- Описаны сигналы и процесс выявления кандидатов (ручной/полуавтоматический).
- Описан процесс упаковки и применения (как пользователь реально использует повторно).
- Есть roadmap на отдельные changes и тестовый след (traceability, уровни проверок, команды).
