## Why

Из пользовательских жалоб повторяется мягкое, но массовое UX-трение: когда человек проходит все задачи уровня, завершение каждой задачи приводит его не туда, куда он ожидает. Вместо возврата к списку задач текущего уровня он попадает в следующий уровень той же задачи и вынужден каждый раз делать лишний переход назад.

Это уже не просто UX-гипотеза, а change на прямую реализацию нового post-success маршрута под `dispatcher-ux`.

## What Changes

- Реализовать post-success UX-поведение, в котором после успешного завершения задачи система возвращает пользователя к списку задач уровня, а не ведёт его сразу в следующий уровень той же задачи.
- В change остаются вопросы реализации:
  - что считать «естественным местом возврата» после успеха;
  - нужно ли различать novice и advanced flow;
  - как это повлияет на current progress model и на контракт task-level transition.
- Change меняет runtime-поведение напрямую.

## Non-goals

- Не отменяет весь progression-contract между уровнями задачи вне post-success точки возврата.
- Не требует в этой волне настраиваемых маршрутов или сложной персонализации flow.
- Не оставляет change на уровне идеи без runtime-изменений.

## Capabilities

### Modified Capabilities

- `task-levels`: может потребоваться пересмотреть post-success navigation между задачей и списком задач уровня.
- `user-progress`: статус и точка возврата после завершения могут быть переосмыслены как часть UX-маршрута.

## Acceptance Criteria

- В дереве OpenSpec существует отдельный implement-change по UX-потоку после завершения задачи.
- Зафиксировано, что change меняет navigation-contract после успеха как осознанное UX-решение.
- Для реализации перечислены затронутые capability и вопросы для проверки поведения.
