## Модель данных (MVP)

Предлагаемый MVP:

- `PromptBlock`:
  - `id`
  - `type` (например: `userText`, `skill`, `dataRef`, `constraint`, `system`)
  - `payload` (JSON, ограниченный по размеру)
  - `enabled`
- `PromptBuilderDraft`:
  - `id`
  - `title`
  - `blocks[]`
  - `createdAt/updatedAt`
  - `projectId?`

Сборка:

- `compilePrompt(draft, context) -> { promptText, metadata }`

Где `context` может включать:

- проект/задача/режим;
- доступные навыки и их версии;
- выбранные данные (с явным источником).

## UX (минимально)

- Toggle между «простой ввод» и «конструктор».
- В конструкторе: список блоков (вкл/выкл), предпросмотр итогового промпта.
- Кнопка «Запустить» использует единый pipeline запуска.

## Совместимость

- Если builder выключен — всё работает как сейчас.
- Если builder включен — итоговый promptText подаётся в тот же запуск, что и текстовый режим.

## Тестирование

- Unit: компиляция блоков, сериализация, лимиты, стабильность порядка.
- Traceability: сценарии builder ↔ тесты.
- (опционально) E2E smoke: собрать блоки → preview → запуск → результат.
