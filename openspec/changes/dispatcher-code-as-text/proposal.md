## Why

Сейчас контроль читаемости кода уже начал работать, но логика и правила пока распределены между разными частями системы. Нужна отдельная подсистема `code-quality-text`, которую можно развивать независимо, без размазывания ответственности и без роста стоимости LLM-разработки.

## What Changes

- Выделяется отдельная подсистема `code-quality-text` как самостоятельный quality-домен.
- Формируется отдельный контур артефактов подсистемы:
  - engine/checker;
  - реестр правил;
  - конфигурация лимитов и режимов запуска;
  - реестр временных исключений (waivers) с owner/reason/targetStage;
  - документация для администраторов и разработчиков.
- Вводятся отдельные команды подсистемы:
  - `npm run quality:text` (рабочие изменения),
  - `npm run quality:text:branch`,
  - `npm run quality:text:repo`.
- Существующие `test:readability*` сохраняются как совместимые алиасы на время migration.
- Интеграция в единый тестовый слой:
  - `test:full` запускает quality-gate подсистемы;
  - quality-gate остаётся deterministic и не требует LLM.
- Добавляются cost-guardrails, чтобы не допустить катастрофического роста стоимости LLM-разработки:
  - LLM не участвует в обязательном пути проверки;
  - optional LLM-режим (если нужен в будущем) выключен по умолчанию;
  - scope по умолчанию ограничен рабочими изменениями;
  - лимиты бюджета и вызовов фиксируются в конфиге подсистемы.

## Capabilities

### New Capabilities

- `code-quality-text`: отдельная подсистема quality-контроля текста кода с собственными командами, конфигом, waiver-политикой и cost-guardrails.

### Modified Capabilities

- `testing-layer`: полный обязательный прогон включает отдельный quality-gate подсистемы `code-quality-text`, который не зависит от LLM.

## Impact

- Инфраструктура качества:
  - перенос текущих readability-проверок в отдельный контур `tools/quality-text/**`;
  - поддержка legacy-исключений через `waivers`.
- Документация:
  - обновление `README.md`, `tools/README.md`, `test/README.md`, `docs/testing-layer.md`;
  - явное разделение инструкций для админов и разработчиков.
- Тестирование:
  - unit/contract проверки подсистемы;
  - traceability к новым сценариям;
  - команды: `npm run test:unit`, `npm run test:traceability`, `npm run test:full`.
