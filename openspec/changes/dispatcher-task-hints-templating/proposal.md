## Why

Сейчас у задач есть подсказки, но они **статичные**. Это ограничивает переиспользование, персонализацию и связность с контекстом (проект, уровень, режим работы, окружение, данные).

В системе уже есть механизм шаблонирования промптов. Подсказки задач должны использовать тот же подход, чтобы:

- не дублировать шаблонизатор и правила форматирования;
- получать подсказки, зависящие от контекста;
- обеспечить единый пайплайн редактирования/тестирования текста (prompts + hints).

## What Changes

- Вводим понятие **templated task hints**: подсказки задач описываются как шаблоны, обрабатываемые тем же механизмом, что и промпты.
- Определяем контракт подсказки:
  - источник (файл/каталог/конфиг);
  - шаблонный синтаксис (наследуем от промптов);
  - входные переменные контекста (минимум: данные задачи, текущий пользовательский контекст, project/level если есть).
- Обеспечиваем обратную совместимость:
  - существующие статичные подсказки продолжают работать;
  - миграция возможна поэтапно (задача за задачей).
- Добавляем тестовую опору (unit + traceability), чтобы шаблоны подсказок не ломались тихо.

## Non-goals

- Переписать все подсказки на шаблоны за один PR — допускается поэтапная миграция.
- Добавлять новый язык разметки/шаблонов — используем существующий механизм промптов.

## Capabilities

### Modified Capabilities
- `task`: подсказки задач становятся динамическими (шаблонными) и могут учитывать контекст.
- `dev-mode` / `projects` (если включены): подсказки могут учитывать данные активного проекта.

## Acceptance Criteria

- Есть единый способ описывать подсказки задач как шаблоны, совместимый с текущей системой промптов.
- Подсказки корректно рендерятся из шаблона при наличии контекста.
- Статичные подсказки остаются рабочими; есть план миграции.
- Добавлены проверки (unit + traceability) и зафиксированы команды.
