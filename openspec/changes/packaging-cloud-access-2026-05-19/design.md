## MVP-рамки

Облачный формат должен начинаться с минимально полезного сценария:

- открыть URL → войти → создать/открыть проект → работать.

## Архитектурные вопросы для проработки

- Аутентификация: какой минимум (email-link, OAuth, allowlist) и как хранить сессии.
- Хранилище: какие данные критичны (проекты, задачи, артефакты, опыт) и какие форматы.
- Изоляция: персональный режим (один пользователь) vs будущая команда.
- Секреты: как исключить утечки промптов/ключей/данных.
- Sandpack/превью: где исполняется (клиент) и какие ограничения в облачном окружении.
- Обновления: миграции схем данных, совместимость версий клиента/сервера.

## Эксплуатация

- наблюдаемость (логи/метрики/трейсы);
- бэкапы и восстановление;
- политика обновлений.

## Тестирование (план)

- Unit: доменная логика (проекты/задачи/права/валидации).
- Integration: API + storage (миграции, изоляция данных).
- E2E smoke: базовый пользовательский путь в hosted версии.
- Live/provider: минимальный чек на реальном окружении (после MVP).
