## Why

На Windows `npm run smoke` может падать при синхронизации onboarding, если временная папка и проект лежат на разных дисках. Корень жалобы конкретный: используется `rename`, который не переживает `EXDEV`.

Проблема блокирует первичную установку и провоцирует опасные ручные workaround'ы вроде создания маркера синхронизации руками.

## What Changes

- Исправляется перенос onboarding-контента между разными файловыми устройствами.
- Синхронизация получает безопасный fallback `rename -> copy + remove` для `EXDEV`.
- Маркер синхронизации создаётся только после реально успешной операции.
- Добавляются проверки на cross-device сценарий.

## Impact

- `npm run smoke` и repair-flow становятся устойчивее на Windows и других multi-device сценариях.
- Снижается риск частично синхронизированного `/onboarding`.
