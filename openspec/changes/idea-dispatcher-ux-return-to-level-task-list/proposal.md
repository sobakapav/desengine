## Why

Из пользовательских жалоб повторяется мягкое, но массовое UX-трение: когда человек проходит все задачи уровня, завершение каждой задачи приводит его не туда, куда он ожидает. Вместо возврата к списку задач текущего уровня он попадает в следующий уровень той же задачи и вынужден каждый раз делать лишний переход назад.

Это не подтверждённый баг действующего контракта, а UX-гипотеза на улучшение маршрута после успеха. Её нужно удерживать отдельно как idea-change в линии `dispatcher-ux`, чтобы потом решить, стоит ли менять navigation-contract продукта.

## What Changes

- Фиксируется UX-idea: после успешного завершения задачи система может возвращать пользователя к списку задач уровня, а не вести его сразу в следующий уровень той же задачи.
- В idea выделяются вопросы для downstream проработки:
  - что считать «естественным местом возврата» после успеха;
  - нужно ли различать novice и advanced flow;
  - как это повлияет на current progress model и на контракт task-level transition.
- Идея остаётся исследовательской и не меняет runtime-поведение сама по себе.

## Non-goals

- Не отменяет текущий контракт продвижения между уровнями задачи.
- Не предписывает готовый implementation-подход.
- Не запускает кодовые изменения без отдельного downstream change.

## Capabilities

### Potentially Modified Capabilities

- `task-levels`: может потребоваться пересмотреть post-success navigation между задачей и списком задач уровня.
- `user-progress`: статус и точка возврата после завершения могут быть переосмыслены как часть UX-маршрута.

## Acceptance Criteria

- В дереве OpenSpec существует отдельная idea-change по UX-потоку после завершения задачи.
- Зафиксировано, что это UX-hypothesis, а не подтверждённый runtime-bug.
- Для downstream change перечислены затронутые capability и вопросы для проверки гипотезы.
