## Why

Сейчас в репозитории уже есть несколько тестовых входных точек и требований к traceability, но нет целостного описания, в каком состоянии реально находится подсистема тестирования: что уже покрыто, где есть дублирование, какие команды обязательны, какие сценарии остаются без понятного слоя проверки.

Без такого исследования сложно принимать решения о развитии тестовой подсистемы: любая оптимизация рискует опираться на неполную картину. Этот change работает как baseline-исследование внутри `focus-quality`.

## What Changes

Этот change фиксирует исследование текущего состояния тестового слоя:

- инвентаризация существующих тестовых команд и их роли;
- карта уровней проверки (static/contract, unit, component/browser, integration, e2e smoke, live/provider);
- анализ покрытия OpenSpec traceability и явных пробелов;
- анализ использования mock/fixture-данных и live credentials;
- перечень основных проблем и направлений для последующих dispatcher/implement changes.

## Non-goals

- Не меняет тестовый runtime и не реорганизует команды запуска в рамках этого change.
- Не добавляет новые тесты как часть исследования.
- Не меняет install-critical инфраструктуру.

## Acceptance Criteria

- Есть понятная карта текущего тестового слоя и его команд.
- Зафиксированы пробелы, дублирование и потенциальные точки упрощения.
- Есть рекомендации, какие follow-up changes нужны под `focus-quality` для развития тестовой подсистемы.
