## Why

Нужен исполнительский change для реализации задачи parent owner.

## What Changes

- Добавить на страницу проекта отдельную architecture-transform панель как первый user-facing слой этой линии.
- Показать в панели:
  - текущие аттракторы `код`, `LLM`, `бюджет`, `дизайн`;
  - vision-роль `AI-трансформации`;
  - ограничения текущей рабочей модели;
  - ближайшие архитектурные волны реализации.
- Привязать панель к уже существующему project overview, а не создавать отдельный раздел или новый route.
- Дать runnable evidence для capability `architecture-transform`, чтобы она больше не оставалась только в coverage-plan.

## Impact

- Пользователь может «пощупать» architecture-transform прямо из UI проекта.
- Project overview становится местом, где архитектура читается как часть продукта, а не как скрытая governance-тема.
