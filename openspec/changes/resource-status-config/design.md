## Context

Раньше `getSystemStatusModel()` одновременно собирал фактические сигналы системы, решал итоговые `ready/warning/blocked`, хранил все пользовательские тексты и вручную пушил элементы в массивы. Теперь серверная сборка фактических состояний ресурсов живёт в `lib/system/resources/internalstate.ts`, а преобразование condition в публичный `Resource` — в `lib/system/resources/publicstate.ts`.

## Goals / Non-Goals

**Goals:**

- Сделать ресурсы первичной моделью диагностики: каждый ресурс имеет `id`, label, набор конфигурируемых conditions и опциональную инструкцию.
- Оставить код диагностики ответственным только за факты и выбор condition.
- Вынести русские описания и инструкции в JSON-конфиг.
- Поддержать переменные шаблона и Markdown-ссылки в текстах.
- Покрыть resolver unit-тестами и связать тесты с OpenSpec capability.

**Non-Goals:**

- Не менять install-critical стек и зависимости.
- Не перестраивать UI системной страницы шире, чем нужно для ссылок в описаниях.
- Не менять контракты LLM, allowlist и onboarding за пределами способа сборки текстов статуса.

## Decisions

- **JSON как источник контента.** Labels, summaries, details и инструкции хранятся в `lib/system/resources/content.json`. Альтернатива с `.ts`-константами проще типизируется, но не решает проблему "контент внутри кода".
- **Condition вместо ручной сборки `Resource`.** Код диагностики возвращает пару `resourceId + condition + values`, а общий resolver строит `Resource` и `Instruction`. Это делает все ресурсы однородными и не навязывает отдельные классы для каждого домена.
- **Простая шаблонизация `{{name}}`.** Этого достаточно для provider label, HTTP code, списков переменных и URL. Более мощный шаблонизатор не нужен и увеличил бы поверхность ошибок.
- **Markdown в существующих строковых полях.** Тип `Resource.detail` остаётся строкой, но UI рендерит её как Markdown. Так сохраняется совместимость модели и появляется возможность ставить ссылки.

## Risks / Trade-offs

- **Опечатка в condition в коде или JSON** → resolver падает с понятной ошибкой, unit-тест проверяет наличие конфигурации для всех ресурсов.
- **Markdown может изменить внешний вид старых строк** → карточка рендерит только inline-friendly элементы, обычный текст остаётся обычным текстом.
- **JSON слабее типизируется, чем TypeScript** → публичные helper-функции валидируют id и condition в runtime, а тесты проверяют покрытие `RESOURCE_IDS`.
