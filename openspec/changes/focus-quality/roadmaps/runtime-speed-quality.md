# Roadmap: Runtime Speed Quality

## Владелец

`focus-quality` владеет этим roadmap и поддерживает его для идей и downstream changes, связанных со скоростью работы системы.

## Контур ответственности

- воспринимаемая скорость интерфейса и лаборатории;
- latency критичных пользовательских действий;
- деградация responsiveness при старте уровня, генерации, проверке и переключении рабочих экранов;
- правила наблюдаемости и evidence collection для performance-жалоб.

## Потоки работ

- `idea-*`: сформулировать гипотезы, границы и критерии полезной скорости;
- `producer-*`: собрать факты, измерения, повторяемые сценарии и baseline по latency;
- `dispatcher-*`: выделить устойчивую performance-подсистему, если проблема станет отдельной линией;
- `fix-*`: закрывать локализованные узкие места после подтверждённого baseline.

## Ближайшие направления

- complaints-to-metrics mapping для жалоб «система тормозит»;
- скорость workbench, preview, start/iterate/check actions;
- различение network latency, LLM latency и UI/runtime latency.

## Критерий полезности

Roadmap считается рабочим, если по нему можно понять, какие жалобы на скорость требуют только дополнительной диагностики, а какие уже готовы превращаться в проверяемые fixes.
