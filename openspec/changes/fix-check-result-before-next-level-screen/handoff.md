## Границы исполнения

- Что входит в этот change: локализация и исправление порядка экранов после успешной проверки, плюс browser/e2e доказательство правильного пользовательского flow.
- Что сознательно не входит в этот change: пересмотр общей модели уровней, redesign экранов не по существу и изменение semantics неуспешной проверки без прямой необходимости.
- Какие решения уже принадлежат parent dispatcher / strategy_root и не должны переоткрываться: сам контракт необходимости успешной проверки и существования результата проверки уже принят в `task-levels`; этот fix не переопределяет его, а возвращает реализацию к нему.
