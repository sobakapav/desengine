## Why

Сейчас после отправки задачи на проверку пользовательский flow нарушает действующий контракт уровней: сначала открывается экран следующего уровня, и только потом показывается экран результата проверки.

Это создаёт сразу две проблемы:

- пользователь видит как будто уже состоявшийся переход на новый уровень до того, как получил итог текущей проверки;
- экран результата проверки перестаёт быть однозначной границей между завершением текущего уровня и дальнейшим движением по задаче.

По действующему контракту успешная проверка должна сначала сформировать и показать результат проверки, а уже затем открывать дальнейший flow следующего уровня или полного завершения задачи.

## What Changes

- Исправить runtime и UX-порядок экранов после успешного `check`.
- Зафиксировать, что экран результата проверки не может появляться после уже начавшегося перехода на следующий уровень.
- Добавить browser/e2e проверку, которая воспроизводит успешный `check` и доказывает правильный порядок экранов.

## Non-goals

- Не пересматривать общую модель уровней и проверки.
- Не отменять автоматический дальнейший flow после успешной проверки, если он уже предусмотрен контрактом.
- Не менять тексты и UX не по существу, если это не нужно для исправления порядка экранов.

## Impact

- Пользователь будет сначала получать понятный итог текущей проверки.
- Переход на следующий уровень перестанет визуально опережать результат проверки.
- Реализация вернётся к уже действующему контракту `task-levels`.
