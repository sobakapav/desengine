## Why

Во входящем документе одна и та же жалоба повторяется как минимум дважды: после одного пользовательского уточнения счётчик прыгает с `0` до `2`, и на уровне фактически не хватает попыток.

Это прямой behavior bug: интерфейс обещает один лимит, а runtime фактически списывает больше.

## What Changes

- Исправляется контракт учёта промптов: один пользовательский `iterate` считается ровно одной попыткой.
- Проверяется весь путь списания лимита:
  - клиент;
  - mutation;
  - prompt-history;
  - повторная проекция task progress.
- Добавляются тесты на отсутствие двойного инкремента после одной отправки.

## Impact

- Пользователь получает ровно столько уточнений, сколько заявлено в интерфейсе.
- Снижается ощущение «система съедает попытки».
