## Context

Текущий progress-flow собирается из prompt history и task progress. Жалоба на скачок `0 -> 2` выглядит как двойной учёт одного и того же действия либо на mutation-слое, либо на проекции состояния после него.

## Goals

- Найти точку двойного учёта.
- Сделать лимит уточнений честным и предсказуемым.

## Non-goals

- Не менять бизнес-лимиты уровней.

## Decisions

1. Жалоба трактуется как high-severity runtime bug, потому что меняет число доступных попыток.
2. Проверка должна проходить по серверному пути, а не только по UI-тексту.
