# Design: Принудительный maxLevel=3

## Решение

- В server layer при чтении `TaskConfig` задаём `maxLevel = 3` поверх распарсенного значения.
- Прогресс пользователя нормализуется существующей логикой, поэтому:
  - добавятся недостающие уровни прогресса;
  - текущий уровень будет ограничен диапазоном `1..3`.

## Риски

- Если глобальный каталог уровней содержит меньше 3 уровней, runtime будет падать при попытке загрузить отсутствующий уровень. В текущем проекте это считается нарушением данных, а не корректируемым состоянием.
