## Context

Жалобы из входящего документа показывают системный сбой первого контакта: пользователь ещё не дошёл до продукта, а уже теряет контекст на этапе install-flow.

Проблема распадается на несколько поверхностных симптомов, но корень один: первый проход рассчитан на слишком высокий implicit technical baseline.

## Goals

- Сделать install/onboarding flow понятным для неразработчика.
- Убрать дубли и лишние ветвления на старте.
- Разделить обязательные действия первого прохода и технические детали, которые можно читать позже.
- Заранее проговорить сетевые ограничения, способные сорвать настройку.

## Non-goals

- Не менять install-critical стек.
- Не переписывать весь публичный docs-контур целиком.
- Не решать runtime-баги сети или LLM через текстовые костыли.

## Decisions

1. Жалобы про дубли, Node.js/npm, терминал, перегруженные секции и tunnel-ограничения обрабатываются как один docs-fix, а не как разрозненные cosmetic правки.
2. Первый проход должен объяснять только необходимый минимум.
3. Ограничения внешних сетевых посредников нужно писать там, где пользователь выбирает способ подключения, а не после падения проверки.

## Risks

- Можно улучшить текст, но не сократить реальную когнитивную нагрузку сценария.
- Чрезмерное упрощение может скрыть важные технические предпосылки.
