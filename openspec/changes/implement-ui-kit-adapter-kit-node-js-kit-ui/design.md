## Контекст

- Родительский change управляет приоритетом и порядком реализации.
- В текущем коде список kit'ов и их runtime dependencies зашиты в `lib/project/ui-kit-config.ts`, а значит адаптер не выражен как отдельная сущность.
- Пользователь уже выбирает `uiKitId` на странице проекта, но системная модель встроенного адаптера и политика кастомизации не артикулированы явно.

## Решение

- Ввести явную системную сущность `UI kit adapter`.
- Вынести встроенные адаптеры в общий каталог `lib/ui-kit/` с единым реестром.
- Оставить project-level `uiKitId` как ссылку на адаптер, а не как самостоятельный ad-hoc конфиг.
- Считать, что runtime dependencies UI kit'ов ставит и везёт сама система.
- Зафиксировать продуктовую политику: ручная кастомизация допустима, но не сохраняется как ценность и может быть снесена при обновлении адаптера.
- Поднять control управления UI kit в верхний слой страницы проекта и явно объяснить встроенную модель пользователю.
