## ADDED Requirements

### Requirement: UI kit adapter является явной сущностью системы

Система SHALL хранить поддержку UI kit'ов не как россыпь ad-hoc настроек, а как явный реестр системных `UI kit adapter`.

#### Scenario: Система читает поддержанный UI kit
- **WHEN** проект, prompt layer или preview-runtime запрашивает `uiKitId`
- **THEN** система резолвит его через явный `UI kit adapter`
- **AND** адаптер хранит как минимум `id`, `title`, runtime dependencies и правила bootstrap

### Requirement: Поддержанные UI kit'ы поставляются самой системой

Система SHALL считать, что поддержанные UI kit'ы поставляются вместе с продуктом, а не устанавливаются пользователем вручную для работы runtime.

#### Scenario: Пользователь выбирает поддержанный UI kit для проекта
- **WHEN** пользователь выбирает `uiKitId` из project surface
- **THEN** система использует только встроенный адаптер из собственного реестра
- **AND** не требует от пользователя отдельно устанавливать npm-пакеты для этого UI kit

### Requirement: UI kit adapters объединены в явный каталог продукта

Система SHALL хранить поддержанные адаптеры в отдельном общем каталоге Node.js внутри продукта.

#### Scenario: Разработчик добавляет новый поддержанный UI kit
- **WHEN** система получает новый поддержанный UI kit
- **THEN** его адаптер добавляется в общий каталог UI kit'ов
- **AND** не размазывается по случайным project/runtime файлам без единого registry

### Requirement: Кастомизация UI kit не считается устойчивой системной ценностью

Система SHALL трактовать ручную кастомизацию встроенного UI kit как допустимое, но незащищённое отклонение.

#### Scenario: Система обновляет встроенный UI kit
- **WHEN** desengine обновляет адаптер или встроенные зависимости UI kit
- **THEN** система не обязана сохранять пользовательскую локальную кастомизацию
- **AND** может перезаписать её как часть controlled reinstall/update flow
