## Why

Сейчас студенты в onboarding-режиме работают над каждым компонентом отдельно. Для LLM-работы в этом мало смысла: контекст дробится, а обратная связь по шагам приходит слишком поздно и фрагментарно.

Есть практический смысл перейти к пакетному подходу: прорабатывать все компоненты и все шаги одновременно, отправлять работу пачками, пачками же получать результат и сразу корректировать его.

Этот подход сложнее в организации, но потенциально эффективнее и может оказаться эффектней по качеству и скорости итераций.

## What Changes

- Создаётся idea-change `idea-batch-component-management` как дочерняя ветка `focus-product`.
- Фиксируется направление: от штучной обработки компонентов к пакетному управлению компонентами и шагами.
- Определяется продуктовая рамка будущих producer/dispatcher/implement changes для пакетного цикла «отправка пачки → получение результата пачкой → коррекция пачкой».

## Non-goals

- Не меняем код, runtime и контракты capabilities в рамках этого change.
- Не вводим немедленно новую тактику выполнения в onboarding без отдельных дочерних changes.

## Capabilities

### Modified Capabilities
- `openspec-tooling`: в дереве изменений появляется idea-узел для пакетной модели работы в onboarding.

## Acceptance Criteria

- Change отображается в дереве как `idea` под `focus-product`.
- Для следующих тактических changes по этой теме используется ссылка на этот parent idea.
- `npm run test:traceability` проходит.

## Тестовая часть change

- Затронутые OpenSpec capability/scenarios:
  - capability: `openspec-tooling`
  - scenario: проверка корректной иерархии change (`parent_change`, `strategy_root`) и traceability-валидации.
- Уровень проверки: `static/contract` (валидация OpenSpec-артефактов).
- Команда запуска: `npm run test:traceability`.
- Mock/fixture-данные: не требуются.
- Live credentials: не требуются.
