## Why

Этот dispatcher ведёт направление UI kit'ов. Релизный вклад текущего среза — зафиксировать проектное переключение kit'ов, HTML-режим, диагностику Sandpack preview и проверяемый smoke; следующий возможный вклад после релиза определяется не автоматически, а только после producer-решения о том, какие kit'ы действительно нужно подключать и когда.

Нужно, чтобы пользователь могла быстро переключать «актуальный UI kit» для Sandpack preview **на уровне проекта** и **без перезагрузки страницы**. Это нужно для:

- быстрого сравнения разных UI kit'ов на одном и том же контенте/коде;
- масштабируемого подключения новых UI kit'ов через единый адаптер;
- режима «без UI kit», когда UI описывается **только HTML-тегами** (без абстрактных компонентов), чтобы система работала даже без подключённых китов.

Дополнительно: сейчас понятие «проект» отсутствует как доменная сущность. Чтобы хранить актуальный UI kit «на уровне проекта» и управлять им, нужен минимальный контракт проекта (пока достаточно в контексте лаборатории/Sandpack).

## What Changes

- Фиксируем `dispatcher-ui-kit` как долгоживущий диспетчер UI kit-направления: текущий релизный срез закрывает переключение, а дальнейшее расширение набора kit'ов допускается только после отдельной producer-проработки.
- Вводим минимальное понятие **Project** (проект) как контейнер для Sandpack preview-конфигурации.
- Добавляем настройку проекта `uiKitId`:
  - значение из списка подключённых kit'ов (через существующую конфигурацию Sandpack UI kit'ов);
  - специальный режим `none` (или эквивалент) — «без UI kit» (только базовые зависимости React).
- Добавляем настройку проекта `uiMode` (или эквивалент), которая управляет тем, как интерпретируется UI-описание:
  - `ui-kit` — компонентный режим для выбранного UI kit'а, сохраняющий совместимость с текущими shadcn-задачами;
  - `html-tags` — разрешены **только HTML-теги** (в этом режиме нет компонентного слоя, не допускаются абстрактные компоненты).
- Вводим контракт «переключения на лету»:
  - изменение `uiKitId` у проекта приводит к пересборке Sandpack payload и перезапуску preview **внутри текущей страницы**;
  - список доступных kit'ов берётся из подключённого конфигурационного списка (а не захардкожен в runtime).
- Добавляем «состояние совместимости» (минимально полезное):
  - если текущий UI-описатель (`uiMode`) и текущий `uiKitId` не подходят для заданного контента, preview не должен «молчаливо падать» — показываем явный статус (например `compatible/unknown/incompatible`) и безопасный fallback (например, рендер ошибки/плашки без краша лаборатории).

## Non-goals

- Унификация токенов (theme/tokens) между kit'ами и перенос единого дизайна — это отдельный большой change.
- Автоматический «перевод» UI между kit'ами при переключении (только безопасная деградация и диагностика).

## Capabilities

### Modified Capabilities
- `level-labs`: лаборатория получает понятие «проект» и настройку актуального UI kit/режима интерпретации UI.
- `task`: Sandpack preview начинает опираться на `project.uiKitId` и поддерживает переключение без перезагрузки.

## Acceptance Criteria

- Пользователь может выбрать `uiKitId` для проекта из списка подключённых kit'ов и увидеть результат без перезагрузки страницы.
- Режим `uiMode=html-tags` работает без UI kit: UI-описание допускает только HTML-теги; preview стабильно рендерится на базовых зависимостях.
- При несовместимости/ошибке UI kit'а лаборатория не падает: есть явный статус и диагностическое сообщение.
- Добавлены/обновлены тесты в общем слое тестирования и зафиксированы команды проверки.
