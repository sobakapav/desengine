## Классы событий (черновик)

Низкочастотные (предпочтительные для MVP):

- `ui_click` (клик по элементу интерфейса, с безопасным идентификатором);
- `ui_shortcut` (горячие клавиши, действие);
- `ui_navigation` (переходы по экранам/панелям);
- `ui_command` (выполнение команды/кнопки);
- `ui_error` (ошибка/тост/диагностика, без персональных данных).

Высокочастотные (опционально и строго ограниченно):

- `pointer_move` / `scroll` / `drag` — только при явном opt-in и с сильной агрегацией/сэмплингом.

## Схема события (MVP)

- `UserActionEvent`:
  - `id`
  - `createdAt`
  - `projectId?`
  - `taskId?`
  - `type`
  - `target` (безопасный id элемента/области, не raw DOM)
  - `payload` (минимум; без текста ввода и секретов)
  - `sessionId`
  - `tags[]`

## Ограничения и приватность

MVP правила:

- по умолчанию не логировать:
  - вводимый текст (в т.ч. промпты как raw input);
  - содержимое файлов/код целиком;
  - любые секреты/ключи.
- хранение локально;
- жёсткие лимиты на объём:
  - TTL (например, N дней) или max size;
  - агрегация high-frequency событий (если включены).

## Агрегация high-frequency событий (если вообще нужно)

Если понадобится логировать движения мыши/скролл:

- sampling (например, 1 событие в X мс);
- bucketing (сетка по экрану, считать heatmap вместо сырых координат);
- запись только во время конкретного исследования/режима (включаем на время).

## Инсайты для пользователя (MVP)

Пример MVP:

- счётчик использования горячих клавиш по ключевым действиям;
- правило: если действие делается ≥K раз мышью и есть hotkey → показать подсказку;
- объяснение: «Вы часто делаете X. Можно быстрее: ⌘K / ...».

## Тестирование (план)

- Unit/contract: валидация схемы событий, редактирование payload, лимиты/TTL, агрегация.
- Traceability: сценарии логирования ↔ тесты.
- Component/browser: факт генерации событий на клике/шорткате (без утечки данных).
