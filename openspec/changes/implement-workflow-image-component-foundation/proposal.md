## Why

Текущая система уже умеет хранить `WorkflowInstance`, `WorkflowStepInstance`, artifacts и Workbench, но реальное исполнение пользовательской работы по-прежнему завязано на модель `уровней`.

Для перехода к пользовательскому слою workflow этого недостаточно:
- пользователь ещё не получает один канонический контур работы `Работаем над workflow`;
- система не показывает набор смысловых пунктов workflow как часть единого результата;
- runtime-проекция по-прежнему считает текущий уровень единственным workflow step, из-за чего новая модель исполнения не может стать базовой.

Этот change должен дать минимальное, но реальное основание для новой модели исполнения без миграции storage и без переписывания всего lab/runtime контура за один раз.

## What Changes

- Ввести канонический workflow типа создания React-компонента по картинке.
- Зафиксировать единый исполняемый шаг `Работаем над workflow`, который становится текущим workflow step для runtime/workbench/prompt context.
- Внутри этого workflow добавить наблюдаемый каталог смысловых пунктов:
  - базовый компонент из UI kit;
  - стилизация;
  - mock-данные;
  - props-контракт;
  - Storybook-сценарии.
- Построить legacy-bridge от текущих runtime/level данных к новому workflow без миграции storage.
- Обновить source-contract/unit-покрытие для новой проекции workflow и workbench/readout слоёв.

## Impact

- Пользовательская работа перестаёт проецироваться в один `level-lab` шаг и начинает проецироваться в канонический image-to-component workflow.
- Workbench и downstream prompt/runtime surface продолжают работать через существующую инфраструктуру, но уже поверх новой workflow-модели.
- Это создаёт рабочую основу для следующего этапа: пользовательский слой сценариев и реальное управление workflow вместо последовательности уровней.
