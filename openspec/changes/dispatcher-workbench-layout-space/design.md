## Что такое «организация пространства экрана» (область)

Набор задач, которые должен покрывать workbench:

- сетка/колонки/контейнеры;
- базовые layout-паттерны (stack, split, sidebar, header+content, card grid);
- responsive правила (breakpoints, min/max, wrap);
- выравнивание и spacing (gap/padding/margin);
- композиция регионов (semantic regions: header/nav/main/aside/footer);
- ограничения и проверка (overflow, min-height, scroll areas).

## Входы и выходы (артефакты)

Возможные входы:

- набор компонентов/блоков (элементы композиции);
- требования к экрану (тип страницы, контентные ограничения);
- референсы (скриншот/макет/описание).

Возможные выходы:

- layout-контейнеры/композиция в виде кода (React/HTML);
- набор design-токенов/констант для spacing и сетки (если есть слой токенов);
- проверочные сценарии (например, Storybook stories для лейаутов).

## MVP инструменты (предложение)

В рамках общего контракта инструментов:

- Layout templates: вставка шаблонов (stack/grid/split/sidebar).
- Grid overlay: визуальная сетка/направляющие поверх preview.
- Spacing inspector: измерение отступов/gap между блоками (с подсказками).
- Responsive preview: пресеты размеров экрана и проверка wrap/overflow.
- Region map: обозначение semantic regions и их структура.

## Интеграция с другими верстаками

Варианты:

1) Layout workbench как самостоятельный верстак-этап (шаг workflow «Собрать раскладку»).
2) Layout tools как набор инструментов, доступный внутри верстака прототипирования/компонента.
3) Гибрид: отдельный верстак + переиспользуемые tools.

## Тестирование (план)

- Unit: вычисления/валидаторы (grid, spacing, responsive rules), сериализация состояния.
- Component/browser: интеракции инструментов (overlay, выбор шаблона, preview размеров).
- E2E smoke: открыть layout workbench → применить шаблон → получить артефакт → он используется в задаче/проекте.
