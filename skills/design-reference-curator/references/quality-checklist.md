# Quality checklist

Before returning the result, verify every item.

## Relevance

- Every image helps answer the actual design question.
- Explicit exclusions and constraints are respected.
- Full product context was not demanded when unnecessary.

## Diversity

- The set contains meaningfully different solution approaches.
- Differences are not limited to visual style.
- Duplicate and near-duplicate screens are removed.

## Source quality

- Every reference has an identifiable source.
- Product names and links are verified rather than guessed.
- Official or primary sources are preferred when available.
- Pinterest and reposts are not treated as final sources when an original can be found.

## Visual usefulness

- Images appear before explanations.
- The relevant interface area is legible.
- Real interfaces are used when the user asked for real examples.
- Weak references were not added merely to reach a target count.

## Explanation quality

- Each explanation states the approach, transferable idea, and limitation.
- The text avoids generic praise and unnecessary product background.
- The final 2–3 directions follow from the references shown.
- The customer-facing formulation uses plain language and does not overpromise.

## Access honesty

- Internal Figma search is claimed only when actual connector or file access exists.
- Restricted or incomplete sources are labeled accurately.
