# Search strategy

## Translate the request into search dimensions

Search from the smallest useful design question rather than forcing a full page taxonomy.

Possible dimensions:

- interaction: add, select, compare, filter, inspect, create, switch, confirm;
- object: table row, language, dashboard, metric, entity, timeline, chart, profile;
- arrangement: inline, side panel, split view, canvas, feed, detail page, wizard;
- constraint: desktop, mobile, keyboard, dense data, no dashboard, no modal;
- neighboring domain: finance, operations, analytics, monitoring, planning, knowledge tools.

Use several queries that vary the domain and wording. A useful pattern may appear in a product from another industry.

## Source priority

1. Official product pages, help centers, documentation, and public demos.
2. Public design systems and product case studies with identifiable screens.
3. Mobbin and other product-screen libraries.
4. Behance, Dribbble, and Awwwards for conceptual breadth.
5. Pinterest only to discover leads that can be traced to stronger sources.

## What counts as a different approach

A reference is meaningfully different when at least one of these changes:

- where the action starts;
- how many steps the user takes;
- whether context remains visible;
- whether data is edited inline or in a separate surface;
- which information becomes primary;
- whether the user scans, compares, follows a sequence, or explores;
- whether complexity is shown at once or progressively disclosed.

A reference is not meaningfully different when only these change:

- color palette;
- border radius;
- illustration style;
- typeface;
- dark versus light theme;
- chart decoration while the surrounding structure stays the same.

## Search expansion

When initial results are repetitive:

- remove the assumed page type;
- search by the user's action rather than the interface component;
- search adjacent industries;
- add terms such as `workflow`, `workspace`, `overview`, `comparison`, `operations`, `monitoring`, or `detail view`;
- search for mature desktop products rather than only design-gallery concepts;
- use negative terms to avoid dominant patterns, for example `not dashboard`, `without cards`, or `non dashboard analytics`.

## Rejection criteria

Reject a candidate when:

- the relevant area is unreadable;
- the source cannot be attributed;
- it repeats an approach already represented better;
- it is a generic mockup with no useful interaction detail;
- it is mostly marketing artwork rather than a product interface;
- it conflicts with an explicit user exclusion;
- the source page no longer supports the claimed context.
