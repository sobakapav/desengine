# Несколько копий задачника на компьютере

Эта инструкция нужна, если у вас:
1. после обновления «ничего не изменилось»;
2. npm run smoke проходит в одной папке, а npm run dev запускается из другой;
3. установлено несколько папок desengine;
4. проект был скачан несколько раз архивом;
5. есть папки вида desengine, desengine-main, desengine-0.1.8, desengine-0.1.9;
6. вы обновили одну копию, а открывается в браузере другая;
7. в терминале один путь, а в редакторе кода открыт другой проект.

## 1. В чём суть проблемы

На компьютере может быть несколько копий задачника:

`C:\Users\Name\Documents\desengine`

`C:\Users\Name\Downloads\desengine`

`C:\Users\Name\Downloads\desengine-0.1.8`

`C:\Users\Name\Desktop\desengine-main`

Вы можете:
- обновить одну папку,
- установить зависимости во второй,
- запустить сервер из третьей,
- а редактировать файлы в четвёртой.

В итоге кажется, что обновление не работает или изменения не применяются, хотя на самом деле используется не та копия проекта.

## 2. Типовые симптомы

### Симптом 1. Обновление прошло, но версия не изменилась

Я обновился, но всё равно старая версия.

Проверить:

`git describe --tags --always` 

Если в разных папках команда показывает разные версии — на компьютере несколько копий проекта.

### Симптом 2. npm run smoke проходит, но npm run dev падает

Частая причина: команды запускались из разных папок.
Например:

`npm run smoke` запустили в C:\Users\Name\Documents\desengine

`npm run dev` запустили в C:\Users\Name\Downloads\desengine

### Симптом 3. Появляется старая ошибка после обновления

Например, вы обновилсь до новой версии, но всё равно видите старую ошибку:

`Cannot find module`

`ENOENT onboarding/levels`

`старый URL сервера доступа`

`старый текст задания`

Возможная причина — запущена старая папка задачника.

## 3. Как проверить, из какой папки запущен проект

Windows PowerShell

В терминале выполнить:

`pwd`

или:

`Get-Location`

Пример вывода:

Path
----
C:\Users\Name\Documents\desengine

Это папка, из которой сейчас выполняются команды.

macOS / Linux

В терминале выполнить:

`pwd`

Пример:

`/Users/name/Documents/desengine`

## 4. Как проверить, что это корень задачника

В текущей папке выполнить:

Windows PowerShell

`dir`

macOS / Linux

`ls`

В корне задачника должны быть файлы и папки примерно такого вида:

`package.json`

`desengine.config.txt`

`app`

`lib`

`tools`

`onboarding`

Главный ориентир:

`package.json`

Если package.json нет — команды запускаются не из корня проекта.

## 5. Как проверить версию именно этой копии

В той же папке выполнить:

`git describe --tags --always`

`git status`

Пример нормального вывода:

`v0.1.9`

и:

`nothing to commit, working tree clean`

Если в одной папке версия v0.1.8, а в другой v0.1.9, значит на компьютере есть несколько копий.

## 6. Частая ошибка: вложенная папка desengine/desengine

Так бывает, если архив распаковали внутрь папки с таким же названием.

Пример:

`C:\Users\Name\Downloads\desengine\desengine`

Проверить:

`pwd`

`dir`

Если package.json лежит во второй вложенной папке, команды нужно запускать именно оттуда.

Но лучше привести структуру к понятному виду:

`C:\Users\Name\Documents\desengine`

## 7. Что делать, если копий несколько

Рекомендуемый порядок:

1. выбрать одну рабочую папку;
2. убедиться, что в ней есть нужные локальные данные;
3. сделать резервную копию важных файлов;
4. остальные копии переименовать или убрать, чтобы не путаться.

Например:

`desengine-old`

`desengine-broken`

`desengine-archive`

Удалять старые копии стоит только после проверки, что из них перенесены нужные данные.

## 8. Что сохранить перед удалением старой копии

Перед удалением или переносом старой папки сохранить:

`desengine.config.txt`

`users`

`локальные файлы с решениями, если они хранятся отдельно`

Не нужно переносить целиком:

`node_modules`

`.next`

`старую папку onboarding без необходимости`

Эти папки лучше пересоздать установкой и синхронизацией.

## 9. Как безопасно перенести конфиг

Windows PowerShell

`Copy-Item "C:\Users\Name\Downloads\desengine-old\desengine.config.txt" "C:\Users\Name\Documents\desengine\desengine.config.txt"`

macOS / Linux

`cp ~/Downloads/desengine-old/desengine.config.txt ~/Documents/desengine/desengine.config.txt`

После переноса:

`npm install`

`npm run smoke`

## 10. Как проверить, что теперь используется правильная копия

На macOS в рабочей папке выполнить:

`pwd`

`git describe --tags --always`

`git status`

`npm run smoke`

`npm run dev`

На Windows:

`Get-Location`

`git describe --tags --always`

`git status`

`npm run smoke`

`npm run dev`

Путь должен быть тем, который выбрали как основной.

# Итого:

У вас должна быть одна рабочая копия задачника.

Из этой же папки нужно:

1. обновлять проект,
2. устанавливать зависимости,
3. запускать smoke,
4. запускать dev-сервер,
5. открывать проект в редакторе.
