# Диагностика установки через npm run smoke

## Когда запускать

Команду `npm run smoke` нужно запускать после:

1. первой установки задачника;
2. обновления до новой версии;
3. переноса проекта на другой компьютер;
4. ручного изменения конфига;
5. проблем с запуском `npm run dev`;
6. ошибки с onboarding, API-ключами или зависимостями.

`npm run smoke` — это быстрая проверка, что локальная установка задачника собрана корректно и основные файлы на месте.

## 1. Перейти в корневую папку проекта

Сначала нужно открыть терминал именно в папке задачника.

Пример для macOS / Linux:

`cd путь/до/desengine`

Пример для Windows PowerShell:

`cd "C:\Users\Имя\Documents\desengine"`

Проверить, что вы находитесь в правильной папке:

`ls`

На Windows PowerShell:

`dir`

Главный ориентир — в папке должен быть файл:

`package.json`

## 2. Проверить Node.js и npm

Перед запуском smoke-проверки нужно убедиться, что Node.js и npm доступны.

`node -v`

`npm -v`

Если команда npm -v не работает, значит npm не установлен или не добавлен в PATH.

## 3. Установить зависимости

Если проект только что скачан или обновлён, сначала выполнить:

`npm install`

Если у вас настроено отдельное npm-окружение для задачника, использовать его:

`npm-desengine install`

После установки не должно быть критических ошибок. Предупреждения `warn` не всегда означают проблему.

## 4. Запустить smoke-проверку

Обычный вариант:

`npm run smoke`

Если используется отдельное npm-окружение:

`npm-desengine run smoke`

## 5. Как выглядит успешный результат

Успешный результат может отличаться по формулировкам, но общий смысл такой:

`Smoke check passed`

`OK`

`Done`

И команда завершается без красной ошибки и без большого стека вызовов.

Если после `npm run smoke` нет ошибки, это значит, что базовая установка прошла проверку.

Но важно: успешный smoke не гарантирует, что вообще не будет ошибок в пользовательском коде задачи. Он проверяет именно установку и базовую конфигурацию проекта.

## 6. Частые ошибки и что они означают

### Ошибка 1. Cannot find module

Пример:

`Error: Cannot find module '../lib/local-config.cjs'`

Что означает:

- в проекте не хватает файла;
- версия установлена некорректно;
- часть файлов обновилась, а часть осталась от старой версии;
- проект мог быть скачан архивом или обновлён не полностью.

Что сделать:

`git status`

`git describe --tags --always`

Затем переустановить зависимости:

`npm install`

Если ошибка сохраняется — лучше обновиться до актуальной версии или сделать чистую установку.

### Ошибка 2. ENOENT: no such file or directory

Пример:

`ENOENT: no such file or directory, scandir '...\onboarding\levels'`

Что означает:

- не найдена папка onboarding/levels;
- onboarding не скачался;
- onboarding скачался не полностью;
- проект лежит в неправильной папке;
- после обновления не подтянулись нужные учебные материалы.

Что сделать:

1. Проверить, есть ли папка:

`onboarding`
`onboarding/levels`

2. Если папки нет или она пустая — пересинхронизировать onboarding.

3. Не создавать .synced вручную, если onboarding реально не скачан.

### Ошибка 3. EXDEV: cross-device link not permitted

Пример:

`EXDEV: cross-device link not permitted, rename ...`

Что означает:

- временная папка находится на одном диске, например C:;
- проект находится на другом диске, например D:;
- система не может корректно переместить onboarding между дисками.

Что сделать:

1. Перенести проект на диск C:, например:

`C:\Users\Имя\Documents\desengine`

2. Запустить установку и smoke-проверку заново:

`npm install`

`npm run smoke`

### Ошибка 4. Smoke прошёл, но доступ к задачам не работает

Возможные причины:

- email не добавлен в allowlist;
- указан не тот email;
- вводится другой email, не тот, который был выдан/разрешён;
- проблема не в установке, а в доступе.

Что проверить:
1. Какой email вводится
2. Есть ли этот email в списке допуска
3. Нет ли опечаток
4. Не используете ли вы запасной email

### Ошибка 5. Smoke прошёл, но npm run dev падает

Это значит, что базовая установка может быть корректной, но ошибка возникает уже при запуске приложения.

Что сделать:

`npm run dev`

Затем смотреть конкретную ошибку в терминале или браузере.

Частые причины:
1. Не подтянулся onboarding
2. Неверный API-ключ
3. Ошибка в desengine.config.txt
4. Ошибка в пользовательском компоненте
5. Проблема с путями на Windows
