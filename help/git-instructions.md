# Зачем нужен Git

Git нужен, чтобы:

1. скачивать задачник из репозитория;
2. обновляться до новых версий;
3. проверять текущую версию;
4. отличать чистую установку от старой или сломанной;
5. понимать, какие локальные файлы были изменены.

Проще говоря: Git помогает правильно устанавливать и обновлять задачник, а не копировать папки вручную.

## 1. Как проверить, установлен ли Git

Открой терминал.

На Windows — PowerShell.
На macOS — Terminal.

Выполни:

`git --version`


Если Git установлен, будет примерно так:

`git version 2.45.0`

Если команда не найдена, значит Git нужно установить.

## 2. Как установить Git

Windows

1. Перейти на сайт Git: https://git-scm.com/download/win
2. Скачать установщик.
3. Установить Git с настройками по умолчанию.
4. После установки закрыть PowerShell и открыть заново.

Проверить:

`git --version`

macOS

В терминале выполнить:

`git --version`

Если Git не установлен, macOS предложит установить инструменты разработчика. Нужно согласиться.

После установки снова проверить:

`git --version`

## 3. Как скачать задачник через Git

Перейди в папку, где хочешь хранить проект.

Например, на Windows:

`cd "C:\Users\Имя\Documents"`

На macOS:

`cd ~/Documents`

Скачай проект:

`git clone https://github.com/sobakapav/desengine.git`

После этого появится папка:

`desengine`

Перейди в неё:

`cd desengine`

## 4. Как проверить, что это Git-репозиторий

В папке проекта выполни:

`git status`

Если всё нормально, будет что-то вроде:

`On branch main`
`Your branch is up to date with 'origin/main'.`

Это значит, что папка связана с GitHub и её можно обновлять через Git.

Если будет ошибка:

`fatal: not a git repository`

значит текущая папка не является Git-репозиторием.

Частые причины:
1. проект скачан архивом .zip;
2. команда запущена не из папки проекта;
3. открыта вложенная папка;
4. папка .git была удалена.

## 5. Что такое ветка

Ветка — это линия разработки.

Проверить текущую ветку:

`git branch`

Пример:

`* main`

Звёздочка показывает текущую ветку.

Обычно вам нужно находиться на:

`main`

## 6. Что значит HEAD detached

Иногда после перехода на конкретную версию можно увидеть:

`HEAD detached at v0.1.8` 

Это значит, что проект находится не на ветке, а прямо на конкретной версии.

Это не всегда ошибка.

Такой режим нормален, если студенту нужно просто использовать конкретный релиз, например `v0.1.8`.

Но в таком режиме не стоит вручную редактировать системные файлы проекта, потому что при обновлении можно запутаться.


## 7. Как перейти на конкретную версию

Сначала получить свежие данные:

`git fetch --all --tags`

Потом перейти на нужную версию:

`git checkout v0.1._`

После этого проверить:

`git describe --tags --always`

`git status`

Затем установить зависимости:

`npm install`

И запустить проверку:

`npm run smoke`


## 8. Как обновиться до свежей версии

Если нужно обновиться до последней версии в ветке `main`:

`git checkout main`

`git pull`

Затем:

`npm install`

`npm run smoke`

Если нужно обновиться до конкретного релиза:

`git fetch --all --tags`

`git checkout v0.1._`

`npm install`

`npm run smoke`

## 9. Что делать, если проект был скачан архивом .zip

Если проект был скачан как архив, внутри него обычно нет Git-истории.

Проверка:

`git status`

Если ответ:

`fatal: not a git repository`

значит папка не подключена к Git.

Лучший вариант

Скачать проект заново через Git:

`cd путь/куда/нужно/скачать`

`git clone https://github.com/sobakapav/desengine.git`

`cd desengine`

`git fetch --all --tags`

`git checkout v0.1._`

`npm install`

`npm run smoke`

Из старой папки обычно нужно перенести только локальные пользовательские данные, например конфиг или папку с прогрессом, если она используется в вашей версии задачника.

## 9. Что нельзя делать

Не рекомендуется:

1. Скачивать новую версию архивом поверх старой папки.
2. Копировать всю старую папку в новую.
3. Удалять .git.
4. Редактировать package.json без необходимости.
5. Удалять onboarding, users или конфиг без резервной копии.
6. Запускать команды не из корневой папки проекта.
7. Работать из вложенной папки вида desengine/desengine, если проект распаковался дважды.

## 10. Частые ошибки

### `fatal: not a git repository`

Значит, текущая папка не является Git-репозиторием.

Что сделать:

`cd путь/до/desengine`

`git status`

Если ошибка остаётся — скорее всего проект скачан архивом. Лучше скачать заново через git clone.

### `pathspec 'v0.1.9' did not match any file(s) known to git`

Git не знает про такой тег.

Что сделать:

`git fetch --all --tags`

`git tag`

Потом проверить, есть ли нужная версия в списке.

### `Your local changes would be overwritten by checkout`

Есть локальные изменения, которые мешают переключиться на другую версию.

Что сделать:

`git status`

Если изменения не нужны:

`git restore `

Если нужно сохранить изменения, сначала сделать резервную копию важных файлов.

### `HEAD detached at v0.1.8`

Это не обязательно ошибка. Это значит, что проект открыт на конкретной версии.

Если нужно перейти обратно на основную ветку:

`git checkout main`

`git pull`
