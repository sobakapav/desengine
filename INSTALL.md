# Установка desengine

Этот документ описывает локальную установку desengine для администратора, который сам поднимает систему на своей машине.
Для обновления уже установленной инстанции используйте отдельный документ [UPDATE.md](UPDATE.md).

## Аудитория и роль

- Администратор: это каноническая пошаговая инструкция локального запуска.
- Пользователь: этот файл полезен только для понимания того, что делает администратор; сам browser-only сценарий описан короче в [README.md](README.md) и `/help`.

Этот документ не дублирует целиком инструкции по allowlist, onboarding и LLM-провайдерам. Для деталей он отправляет в профильные документы.

## Короткий маршрут первого запуска

Если проходите установку впервые и не хотите разбираться во всех настройках заранее, держитесь этого маршрута:

1. Установите `Node.js` и проверьте `node -v`, `npm -v`.
2. Выполните `npm install`.
3. Создайте `desengine.config.txt` из `desengine.config-example.txt`.
4. В `desengine.config.txt` выберите `LLM_PROVIDER` и заполните ключ только для этого провайдера.
5. Оставьте `ALLOWLIST_*` и `ONBOARDING_REPO_URL` как в шаблоне, если у вас нет отдельной рабочей инфраструктуры.
6. Выполните `npm run dev` и откройте [http://localhost:3000](http://localhost:3000).

Всё остальное в этом файле нужно, когда первый проход упирается в конкретную подсистему.

## Что понадобится

- macOS, Windows или Linux
- актуальный `Node.js` вместе с `npm`
- браузер

`desengine` работает с локальными файлами пользователя, поэтому запуск предполагается прямо на хост-машине, а не внутри изолированного контейнера.

Проектные данные и пользовательское состояние разделены:
- `/onboarding` содержит versioned onboarding-контент: открытые материалы уровней в `levels/**`, скрытые level prompts в `prompts/levels/**`, task config, `base.png` и `variants.png`;
- `user/` содержит локальный прогресс, рабочие файлы задач и историю промптов.

## 1. Установите Node.js и npm

Нужен обычный установленный `Node.js`, в комплекте с которым идёт `npm`.

Проверьте, что оба бинарника доступны:

```bash
node -v
npm -v
```

Если `node` есть, а `npm` не находится, самый надёжный путь — переустановить Node.js из одного источника, а не чинить `npm` вручную:

- либо через официальный установщик с сайта Node.js;
- либо через ваш пакетный менеджер (`brew`, `winget`, `apt`, `dnf` и т.д.).

После переустановки снова проверьте:

```bash
node -v
npm -v
```

## 2. Установите зависимости проекта

Из корня репозитория выполните:

```bash
npm install
```

## 3. Создайте локальную конфигурацию

Переименуйте [desengine.config-example.txt](desengine.config-example.txt) в `desengine.config.txt`.

Это можно сделать любым привычным способом:

- через проводник/Finder;
- через редактор кода;
- через командную строку, если вам так удобнее.

Для первого запуска обычно не нужно переписывать весь файл. Проверьте только три вещи:

- `LLM_PROVIDER` указывает на того провайдера, ключ которого у вас действительно есть.
- Ключ заполнен только у выбранного провайдера.
- `ONBOARDING_REPO_URL` оставлен каноническим или заменён на ваш реальный onboarding-репозиторий.

Остальные значения можно оставить шаблонными, если у вас нет отдельной инструкции по окружению.

Шпаргалка по ключевым полям:

```env
LLM_PROVIDER=openai
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-4.1-nano
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
GEMINI_API_KEY=
GEMINI_MODEL=gemini-2.5-flash
GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta
CLAUDE_API_KEY=
CLAUDE_MODEL=claude-haiku-4-5
CLAUDE_BASE_URL=https://api.anthropic.com/v1
CLAUDE_MAX_TOKENS=4096
ZAI_API_KEY=
ZAI_MODEL=glm-5v-turbo
ZAI_BASE_URL=https://api.z.ai/api/paas/v4
ALLOWLIST_BASE_URL=https://example.com/allowlist/
ALLOWLIST_SALT=replace-with-random-secret
ONBOARDING_REPO_URL=https://example.com/desengine-onboarding.git
```

В шаблоне уже оставлены типовые значения для моделей, allowlist-настроек и URL onboarding-репозитория. Обычно вручную меняются только `LLM_PROVIDER`, ключ выбранного провайдера и при необходимости реальный адрес onboarding-репозитория.

## 4. Запустите приложение

Из корня репозитория:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## 5. Что вы увидите

- На `/` приложение покажет страницу состояния системы, список следующих шагов и ссылки на `/auth`, `/system`, `/help` и защищённые маршруты.
- Если допуска ещё нет, защищённые маршруты переведут на `/auth`, где показаны статусы системы и allowlist-форма.
- До успешной allowlist-проверки рабочая часть лаборатории не откроется.
- Даже если `OPENAI_API_KEY` не задан, `/auth` и `/system` всё равно должны открываться.
- Если `/onboarding` отсутствует или неполон, приложение должно явно показать проблему с onboarding-контентом вместо тихого fallback к старым корневым каталогам.
- На первом запуске система сама пытается подтянуть `/onboarding` из `ONBOARDING_REPO_URL`.
- Если статус onboarding не становится `ready`, откройте `/system` и используйте кнопку `Обновить onboarding` как явный repair path.
- Пользовательский browser-only сценарий после этого выглядит так: `/` → `/auth` → `/tasks` или `/levels`.

## 6. Что важно про каталог `user/`

- Каталог `user/` создаётся автоматически по мере работы.
- В нём живёт всё, что пользователь сделал сам: прогресс, рабочие файлы задач и prompt-history.
- Его не нужно коммитить и не нужно включать в обычное обновление проекта.
- Если удалить `user/` целиком, приложение не сломается: это просто полный reset пользовательской работы.
- Обычный reset отдельной задачи тоже должен удалять её пользовательский каталог полностью.

## Протокол пользовательского прогона

Если вы тестируете установку на живом человеке, попросите его идти по шагам ниже и вслух проговаривать всё, что кажется непонятным, лишним или тревожным.

Попросите пользователя:

1. Открыть этот файл и пройти установку строго по инструкции, не подглядывая в другие документы.
2. Самостоятельно проверить, есть ли у него `node` и `npm`.
3. Установить зависимости проекта.
4. Переименовать `desengine.config-example.txt` в `desengine.config.txt`.
5. Заполнить только обязательные для первого запуска переменные: `LLM_PROVIDER` и ключ выбранного провайдера.
6. Запустить приложение.
7. Открыть приложение в браузере.
8. Объяснить своими словами, что он видит на стартовом экране.
9. Попробовать пройти допуск через allowlist.
10. Сказать, в какой момент он почувствовал, что “всё работает”.

Во время прогона фиксируйте:

- на каком шаге человек остановился;
- какие слова или термины пришлось объяснять отдельно;
- понял ли человек разницу между установкой, настройкой `desengine.config.txt` и входом через allowlist;
- смог ли он без подсказки открыть именно корневой маршрут `/`;
- понял ли он, почему до допуска попадает на `/auth`, а не сразу в задачи;
- пришлось ли ему чинить `node`, `npm` или shell вручную;
- возникли ли неожиданные ошибки в `npm install`, `npm run build` или `npm run dev`.

После прогона полезно задать пользователю 3 коротких вопроса:

1. “На каком шаге инструкция перестала быть очевидной?”
2. “Что бы вы переписали в этой инструкции в первую очередь?”
3. “После этого опыта вы бы смогли повторить установку ещё раз без посторонней помощи?”

## Если что-то пошло не так

### `npm: command not found`

Значит Node.js установлен некорректно или shell не видит `npm`. Не создавайте `npm` вручную. Надёжнее переустановить Node.js целиком и убедиться, что после этого работают обе команды:

```bash
node -v
npm -v
```

### `next build` падает на TypeScript

Это уже ошибка проекта, а не установки. Сохраните хвост вывода `npm run build` и разбирайте его как обычную code/build проблему.

### Открывается только статусная страница

Это нормально, если:

- не задан `OPENAI_API_KEY`;
- не настроен allowlist;
- email ещё не прошёл allowlist-допуск.

Сейчас таким статусным entry point по умолчанию является `/`, а диагностические детали также доступны на `/auth` и `/system`. Список задач на `/tasks` остаётся защищённым маршрутом.
